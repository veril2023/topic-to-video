## A. 内容与叙事

## L 类 · 技术栈级通用经验（继承自通用生产体系，跨题材适用）

### L-01 禁滚动条带 / 动态计数器类视觉母题
- **现象**：连续 5 集用"计时器"母题，用户反馈"模糊看不清"，5 集全部重渲。
- **根因**：动态元素的标签被 absolute 压在变化中的元素上，字号缩到 20px 以下。
- **规则**：新母题必须过 Legibility 门——最小字号 ≥24px、标签做成静态独立行、probe 时 100% 放大逐张看。滚动条带/动态计数器默认禁用。

### L-02 改完节拍/母题/文案后，旧 probe 结论全部作废
- **现象**：改完节拍直接交付，用户报音画偏移。
- **规则**：任何重渲 = 全部质检门重跑，不打折；marks 有多少个就抽多少帧。

### L-03 抽查 ≠ 验证
- **现象**：抽查 3 帧就宣称"已逐帧验证"，用户随即反馈偏移。
- **规则**：声称"已验证"前先自问——这个断言覆盖了我实际检查过的范围吗？

### L-04 句级驱动：元素不能挂在"顺眼的"别的句子上
- **现象**：某元素挂第 5 句而它表现第 4 句内容，画面比声音晚 5.8s。
- **规则**：每个元素的入场时间必须来自它对应那句的 `mk(scene, idx)`；禁 forEach 循环变量写时间。

### L-05 场景进入必须有完整首拍
- **现象**：某场景前 2.6s 只有标题，声音已在读正文。
- **规则**：场景起点 0.6s 内，首句的完整视觉（标题+插画+关键行）必须全部在场。

### L-06 禁止浅色场景 / 禁止纯文字大字卡
- **现象**：用户反馈"加入图片不要纯文字""背景全采用深黑色"。
- **规则**：全场景深黑 `#07080C` 系；每场景 ≥1 内联 SVG 意会插画；场景 1 前 2 秒见图。

### L-07 死画面自动门
- **规则**：`tools/_check_sync.py` —— 每场景 0.6s 内有事件 / 相邻事件间隔 ≤4s / 每句都有事件 / unparsed 时间表达式 = 0。不过不许渲染。

### L-08 Windows 环境
- 渲染必须在 sandbox 外跑；端口残留先清；删文件用 `python -c "import shutil; shutil.rmtree(...)"` 并回读验证。
- 大段中文内容不要直接写进 .py 源码（全角引号会被规范化成 ASCII 引号 → SyntaxError），抽到独立文本文件读入。
- 同一文件不要并行发多个 Edit（会静默覆盖），必须串行。

### L-09 程序化生成的图片必须逐张实际看一眼
- **现象**：连续两次"魔数通过 + 尺寸对 + 比例对"却存在元素重叠、文字被裁切。
- **规则**：交付前先 Read 图片确认，再写"已完成"。

### M-01 结构不能照搬读书系列
- **现象**：v1 直接套用 `vertical-book-video` 的 8 场景骨架（含"自证题""工作单""明日动作"），而那是"教一个人改行为"的结构。
- **根因**：数学观众的诉求是**理解与震撼**，不是行为改变。
- **规则**：数学系列用**七幕升维结构**（奇景→困局→动手→造物→穿透→升维→追问）。**不设"工作单/明日动作"**。

### M-02 传说必须标注，不许当史实讲
- **现象**：希帕索斯投海、伽罗瓦决斗前夜、帕特农黄金比——流传极广，但多数是后世演绎。
- **规则**：一律 **T3 标**，且**配音与画面双标**（不能只在文档里标）。**不许拿史实失真换笑点。**

### M-03 故事必须有镜头，不能只写在文案里
- **现象**：v2 的 ep01 有一段很好的苏美尔故事，但画面只有"时间地点三件套 + 神庙插画"——观众听到的是广播剧。
- **规则**：建立**叙事分镜层**，每个故事幕拆 4–8 镜，标镜型（EST/ACT/CU-prop/CU-face/SYM/SCHEMA），**分镜板先于动画代码存在**。

### M-04 抽象句必须有画面承接
- **现象**：配音在讲抽象（"羊和大麦不能相加"），画面还停在上一个实物。
- **规则**：**R4 —— 抽象句必须落在 SYM 或 SCHEMA 上**（例：让加号亮起、闪烁、裂开碎成灰）。

### M-05 升维句不能是总结
- **现象**："这一集我们讲了数的起源"——这是目录，不是升维。
- **规则**：QC-16 —— 把升维句单独拎出来读，**若只是本集内容的总结 → 不合格**。每集试 ≥3 型，选最不像总结的。

### M-06 母题单轴撑不到 67 集
- **现象**：只靠"发明 vs 发现"二选一，后半段会退化成分类题。
- **规则**：升级为**双主线**（外线记分 + 内线"有人愿意相信一个当时没用的东西"）。

### M-07 "活泼"靠文本工程，不靠音色卖俏
- **规则**：幽默 8 法 + 入思三件套 + 反油腻纪律。**幽默 ≤4 处**；**删掉它信息量不减就该删**；**不许拿数学人物的悲剧做段子**。

## B. 技术链路

### M-08 判断模型是否存在，唯一判据是实机调用
- **现象**：曾检索得到"`agnes-image-2.5-flash` 没有文档页 → 不确定存在"的结论；实测 `GET /v1/models` **证实它存在且可用**。另外检索到的 Base URL `apihub.agnes-ai.com` 与实际配置 `api.agnes-ai.cn` **不同**。
- **规则**：**任何模型名/端点写进生产流程前，必须先用 curl 实测**。实机结果与检索结果冲突时，**以实机为准**，并就地标记旧结论作废（保留错误留痕）。

### M-09 Agnes 参数坑（照抄会被打回）
- 比例字段是 **`ratio`**（合法值 8 个，含 `9:16`）；`size` 传了**静默忽略**；`resolution`/`n` **不支持**；`9:16` 实际出 **736×1312**；要求 `#07080C` 实际返纯黑 → **后处理压底必需**；免费档有队列，重试即成功。

### M-10 能不用视频 API 就不用（这不只是省钱）
- **判据**：画面里的"动"，若观众可能把它当**数学证据**看 → 必须由程序算（A0/A1）。
- **理由**：AI 视频里的球会漂移变形违反重力；观众一旦看出"这球不对劲"，**整集数学可信度一起崩**。
- **另白送三好处**：免费、可重跑、可逐帧检查（AI 视频的帧只能重生成，不能修）。

### M-11 历史名人不用 AI 造脸
- **根因**：人格权 + 误导观众。
- **规则**：用公有领域版画 / 无脸剪影背影手部 / SVG 重绘。

### M-12a AI 素材不得作为证据
- **规则**：只当**示意/气氛**，统一加"示意"角标；"这个东西真长这样"必须走 L4 实拍或 L1 重绘。

## C. 验收纪律

### M-13 不说"我用眼睛看完了每一帧"
- **现象**：一集约 5040 帧，硬说"看过了"比不说更危险（会让自己误以为安全）。
- **规则**：只说"**每一帧都过了机器判定 + 关键帧与高难段逐张目视**"，并交出四份报告（21-A/B/C/D）。

### M-14 机器查不出"难看"和"看不懂"
- **现象**：曾出现"魔数通过 + 尺寸对 + 比例对 + 字节数合理"全对，但**标题被右边缘裁掉**。
- **规则**：程序化生成的图片**必须逐张 Read 确认**后再报完成。

### M-15 抽查 ≠ 验证
- **规则**：交付前必须全锚点抽帧 + 从最终 mp4 再交叉验证一轮。**改完文案/节拍后，旧 probe 结论全部作废。**

### M-16 通俗化是顺序问题，不是词汇问题
- **规则**：**身体锚 → 可数锚 → 图像锚 → 名字锚**，顺序不可反。**复述测试**：一句话版本（≤25 字）必须用不到任何术语。

## D. 本机环境

### M-17a 大段中文不要直接写进 .py
- **现象**：中文全角引号（""''）写入 .py 时被规范化为 ASCII `"` → SyntaxError。
- **规则**：内容抽到独立文本/json 文件读入。

### M-18 删除文件不要用 `rm` / `Remove-Item`
- **现象**：本机被 safe-delete 垫片接管，回收站失败即静默不删（看着"成功"其实没删）。
- **规则**：用 `python -c "import shutil; shutil.rmtree(...)"` 并**回读验证**。

### M-19 渲染与端口
- **规则**：渲染必须在 sandbox 外（`dangerouslyDisableSandbox`）；Chrome 长渲染会随机崩 → 断点续渲（跳过已存在帧）；端口每集递增（CDP 9431+2(N-1) / HTTP 8891+(N-1)）。

### M-20 同一文件不要并行发多个 Edit
- **现象**：两个 Edit 都返回 success，但后写的基于旧快照，会**静默覆盖**前一次。
- **规则**：同一文件的多次编辑必须**串行**。

### M-21 TTS 没有句级时间戳
- **规则**：MiniMax 无 SentenceBoundary → 一律 `silencedetect` 反推句级节拍；**禁止用字符数比例直接当节拍**。

## E. ep01 实拍踩坑（2026-10-16，全部由逐帧目视 + 机器判定发现）

### M-22 `childNodes` 会混入换行文本节点 → 整个 seek() 静默中断
- **现象**：`g('a6-strike').childNodes` 里含 HTML 换行产生的 Text 节点，`nodes[i].setAttribute is not a function` 抛异常。该 updater 之后注册的**全部** updater（含字幕、幕级清场）从此不再执行，画面看起来"只是字幕没出来"，实则整条渲染链断裂。
- **规则**：SVG 里遍历子元素一律用 **`element.children`**（只含 Element），不用 `childNodes`。
- **衍生**：QC 必须包含"在浏览器里 seek 一次并捕获 pageerror"这一步；只截图看不出这种错。

### M-23 元素不会自己退场 —— 必须建幕级硬清场表
- **现象**：所有 updater 只写 `vis(...)` 的进入时间，几乎不写退场时间 → 第 207 秒的画面上同时叠着幕1 的追问、幕6 的落点大字、幕7 的圆盘与记分牌。**跨 4 幕内容同屏**。
- **规则**：建一张 `OWN` 表（元素 id → 硬隐藏时刻），在 `seek()` 末尾对 `t >= 该时刻` 的元素强行置 `opacity:0`。幕级清场是对"每个 vis 写对退场"的兜底，两者都要有。

### M-24 同区域的文字必须在时间上互斥
- **现象**：陶筹标签 `圆锥`(x280,y930) 与加号题的 `大麦`(x325,y928) 空间重合，两者同时满不透明度 → 叠印成乱字。
- **规则**：屏幕上同一区域不允许两层**满不透明度**文字。换镜时让旧镜先退到 0 再进新镜；只有纯照片之间才允许 crossfade。

### M-25 字幕折行必须由宽度反推，不能拍脑袋
- **现象**：44 字长句被强行并成 2 行，第二行 25 字 × 42px = 1050px，横穿整屏并顶到画面边缘。
- **规则**：`单行最大字数 = floor(安全宽 / 字号)`。安全宽 810px、字号 40px → 19 字/行；超过 2 行允许 3 行（基线 40/98/156，都在 y≤1520 内）。**交付前用脚本把全部 cue 打一遍，报告最长行字数**。

### M-26 每一幕的"第一个画面"必须早于该幕首句
- **现象**：幕3 从 64.84s 起，但里面所有图形都在 67.48s 之后才出现 → **2.6 秒纯空镜**；幕5 从 134.17s 起，图形 137.10s 才来 → 2.8 秒空镜。
- **规则**：每幕第一个 element 的 in 时间 = `min(该幕首句 start − 0.25s, 幕起点)`。空镜超过 0.3s 就补一张标题卡或回收上一幕的图。

### M-27 用机器统计"连续空帧"，别靠肉眼
- **规则**：QC 脚本按 `L < 60` 判"实质黑帧"，统计连续段；**>4 帧（0.167s）即报**。逐帧看了几十张也发现不了"第 134.05 秒整帧是黑的"。

### M-28 暗底照片入库前必须按目标卡片长宽比裁切
- **现象**：博物馆实拍里骨器只占画面 12% 宽，`object-fit:cover` 到 790×550 的横卡 = 只剩一条糊带，观众看不到刻痕。
- **规则**：先算目标卡片长宽比 → 用 PIL 按该比例裁到实物本体 → 再进 CSS。裁完**必须 Read 图片确认**。

### M-29 CDP 渲染器必须主动断连并强制退出
- **现象**：`server.close()` 但没 `browser.disconnect()`，node 事件循环被 WebSocket 挂住 → 进程不退出、**8920 端口一直占着** → 下一次运行直接 `EADDRINUSE`，且此前那次的 `probe done` 已写出，容易被误判为"跑完了"。
- **规则**：`finally` 里依次 `browser.disconnect()` → `chromeProc.kill()` → `server.close()` → `server.closeAllConnections()` → 300ms 后 `process.exit()`。

### M-30 交付给用户的成片时长按 24fps × 总时长取整核一次
- **规则**：`frames = ceil((T.total + tail_pad) × 24)`；渲染后清点磁盘帧数，与公式对不上就是漏渲。

## F. ep01 第二轮：从"14 段全黑"到 0 段（2026-10-16 下午）

> 背景：第一版全片跑完，**机器判定**发现 14 段、共约 12s 的"只有字幕、主画面全黑"。
> 下面每一条都是"先量出来、再改、再量回去"的，不是看着像。

### M-31 SVG 内层 `<g>` 的 `transform-origin` 计算值是 `0px 0px`
- **现象**：`#a3-spare` / `#a5-n5` 用 CSS `scale()` 入场，元素被往**右下**推，越靠右偏得越多，越过右安全界。父 `<svg>` 的 origin 是 `500px 350px`，但内层 `<g>` 实测是 `0px 0px` —— 不是继承父的中心。
- **规则**：全局加一条 `#stage svg g{transform-box:fill-box;transform-origin:center}`。这条规则一次修好两处越界。
- **怎么发现的**：写 `verify/probe_tf.js`，在页面里对可疑元素 `getComputedStyle(n).transformOrigin` 打出来看。**不要靠读代码猜 origin。**

### M-32 CSS `style.transform` 覆盖 SVG `transform` 属性
- **现象**：幕2 加号崩解写的是 `setAttribute('transform', 'translate(...) rotate(...)')`，而同一个元素每帧又被 `set()` 写了 `style.transform` → **属性被完全忽略**，崩解只看得见淡出。
- **规则**：一个元素只能有一条 transform 通道。要么全用 CSS，要么全用属性。本项目统一用 CSS：把位移/旋转/缩放**拼成一个字符串**传给 `set()`。改完回读 `el.style.transform`，确认拿到 `matrix(0.996, 0.087, -0.087, 0.996, 12, -5)` 这种实际值。

### M-33 拍级交接契约：**进场拍的第一个内容元素必须在下车拍开始变暗之前达到 o=1**
- **现象**：`vis()` 的出场是 `outAt` 之后先 `OUT_HOLD` 再降。只要入场点晚于 `outAt + OUT_HOLD − inDur`，交接处两块会同时落在 0.3–0.5，**细线图形（时间轴/链条/刻痕）此时直接读成纯黑**。原版全片 14 段 / 12s 全黑，**全部**由这一条被违反造成。
- **规则**：① `vis()` 里加 `OUT_HOLD = 0.55`；② 逐条核对"入场点 ≤ outAt + OUT_HOLD − inDur"。
- **量化残样**（修前 → 修后，主画面峰值亮度）：
  | 位置 | 原因 | 修前 | 修后 |
  |---|---|---|---|
  | t≈41.2（2C→2D） | 陶筹入场晚 0.57s | 89 | **211** |
  | t≈59.0（2E→2F） | 图式入场晚 1.35s | 79 | **219** |
  | t≈137.5（5A→5B） | 链条首节点晚 0.45s | **45** | **217** |

### M-34 设计上**同框嵌合**的复合图要"共存后抽走"，不要交叉溶解
- **现象**：幕2 的 2E（大麦＋羊＋加号）与 2F（陶筹＋问号）看着像两张要互相溶解的图，实测版面是**互相嵌合**的 —— 注解正好落在对方的空隙里（大麦 x271-379、正文 x387-693、羊 x701-809，同行不叠；两个「？」y 相差 382px）。交叉溶解让两块细线图在交界处同时落到 0.4，峰值亮度掉到 79。
- **规则**：给 `vis()` 加第 6 参数 `hold`，这种关系传 `hold=0`：等入场块 o=1 之后再快速抽走出场块，交界处始终有一块是 o=1。
- **判据**：先量两块的 ink bbox 是否真的互斥，再决定"溶解"还是"抽走"。别凭感觉。

### M-35 幕末清场必须是**淡出**，不能瞬时置 0
- **现象**：`t >= E` 直接把 opacity 置 0 → 幕边界出现全黑（幕1→2 等 5 处各 0.6s，幕6→7 达 1.7s），因为下一幕第一个元素还没淡入。
- **规则**：`OWN` 表清场在 `[E − OWN_FADE, E]` 上按比例压暗；`OWN_FADE = 0.40`。并且**幕末边界取"下一幕首句起点 − 0.15"**，跨过配音的句间静音，与下一幕的提前入场形成交叉溶解。
- **写法坑**：清场用 `n.style.opacity = Math.min(cur, k)` —— **只压不抬**，否则会覆盖 updater 已经算好的入场进度。

### M-36 空画面判据用**峰值亮度**，不能用亮像素计数；阈值必须标定并**双档输出**
- **现象**：`a5-chain` 全不透明时，超过阈值 75 的像素只有 **2967** 个 —— 与真正空画面的数量级相同，计数法会大量误判。
- **规则**：判据 = 主画面区（y < 1330）**最大亮度**。背景 `#07080C` 亮度 ≈ 7；交付档阈值 **60**（对比度约 8×，手机屏稳定可辨）。
- **同时输出严格档 100**，不掩盖问题：ep01 最终 100 档 0 段、60 档 0 段。
- **为什么 100 是错的**：峰值 79 / 89 那两帧逐帧目视过，人物与器物轮廓清清楚楚，判成空画面与目视不符。
- **t < 0.5s 的开场淡入允许留黑。**

### M-37 安全区与重叠检测：量"墨迹"，不量盒子；文本 Range 盒要留 slack
- **现象**：`getBoundingClientRect()` 对居中的块级 `<div>` 返回**整行宽**的盒子 → 每个时刻报 8 处"越界"，全是假警报；`Range.getClientRects()` 给 `<text>` 的盒子含最后一行的**右边距**，比实际墨迹宽约 14px → 又误报 9 处字幕越界（实测真实墨迹 x=160..892，未越界）。
- **规则**：SVG 几何用 `getBoundingClientRect`，非 SVG 叶文字用 `Range.getClientRects()`，**文字盒留 14px slack，几何盒留 0**。改完 0/5184。

### M-38 沙箱 `safe-delete` 会拦批量删除，且**静默拒绝**
- **现象**：`shutil.rmtree('frames_ep01')` 返回 `[SAFE_DELETE_BULK_CONFIRM_REQUIRED] {"count":5184,"threshold":50}`。因为渲染器是"文件已存在就跳过"，日志照打 `frames: 5184`，看起来渲染完了，**其实一帧没渲**。
- **规则**：**用 `os.rename()` 改名腾目录**（元数据操作，不被拦），改完回读 `os.path.isdir` 与新目录文件数确认。
- **衍生**：任何"清空目录后重渲"的流程，先确认目录真的空了 —— 别信命令没报错。

### M-39 修复有效性先用**局部亮度探针**验，再花时间全渲染
- **做法**：`verify/probe_dark.js <t1> <t2> ...` —— 只对嫌疑时刻前后 ±1.3s 逐帧截图（`Page.captureScreenshot` + `clip ... scale:0.5` → 540×665 JPEG），同时打出一条结构判据（同帧最强元素的**有效**不透明度 = 自身 × 全部祖先）。
- **收益**：ep01 用它把 3 处修复 + 6 处幕边界一次性验完（379 帧，约 1.5 分钟），**避免了 3 次 6.6 分钟的全渲染**。全片渲染 + `qc23` 只作最终确认。
- **规则**：全渲染是最后一步，不是第一步。

### M-40 只修**被量到**的问题，不要顺手"改进"没出问题的幕
- **现象**：本轮我曾把幕3 的入场从 `mk(3,0)-0.70` 提前到 `-1.05`，理由是"幕2→幕3 交接也该收紧"。但 QC-23 的失败清单里**根本没有** 64.x 这一段；而且提前后幕3 的标题大字（top:610）会与幕2 的图式（top:600）**空间重叠** 0.4s，等于拿一个实测通过的点去换一个 QC-24 风险。
- **规则**：改动的范围 = 失败清单的范围。想扩大范围，先把扩大范围的理由也**量出来**。

### M-41 探针脚本里的 CDP 目标页要判空
- **现象**：`(await browser.pages())[0]` 在 Chrome 还没开页时是 `undefined` → `TypeError: Cannot read properties of undefined (reading 'createCDPSession')`。
- **规则**：`const pgs = await b.pages(); const pg = pgs.length ? pgs[0] : await b.newPage();`

### M-42 `os.path.join` 里写 printf 格式要小心双 `%`
- **现象**：`'qc_sheet_list_%%02d.jpg'` → `TypeError: not all arguments converted during string formatting`。
- **规则**：格式化只在**最外层**用一次 `% index`，文件名模板里写单 `%02d`。

### M-43 只看"元素入场"的对账会漏判"画面其实是死的" —— 必须补一条**像素**判据
- **现象**：`qc21d_align.js`（看元素有效不透明度是否跨过 0.15）报 15/63 句"无对应画面事件"。
  但那 15 句里有一部分只是**事件早入场了、此刻在延续**，画面并不死；反过来，
  它**完全抓不到**另一类问题 —— ep01 有 **4 句配音期间画面一个像素都没变**
  （相邻帧平均绝对差 = 0.000），最长那句 **5.47s**，另 8 句只有 0.009-0.253 级差。
- **规则**：逐句配音对成片帧求**最大相邻帧差**，作为"这句有没有动"的硬指标
  （`verify/qc21d_motion.py`）。DOM 对账管"有没有新事件"，像素对账管"有没有在动"，两条都要。

### M-44 帧差判据的阈值要按"有没有动"定，不能按"动得明不明显"定
- **教训**：一开始把阈值定在 0.30 级，结果连**缓慢推镜**都被判成静态 ——
  实测一次 16px / 0.9s 的平移只有 0.253 级差，可它明明是在动。
- **正确分档**：冻结 = `maxAdj < 0.02 且 span < 0.05`（一个像素没变，必改）；
  近静 = `maxAdj < 0.10`（提示，人工确认）。
  0.02 的位置有依据：同一张 JPEG 重复编码的噪声实测 0.005-0.02 级。

### M-45 长句必须给"永不停止的镜头呼吸"，不能只写入场动画
- **现象**：所有 updater 只写"入场"，入场一结束元素彻底静止 → 长句变成幻灯片。
- **对策**：`oscFrag(t)` 对 `#stage` 的**全部直系场景元素**施加**同一相位**的极慢往复
  位移 + 缩放：`translate(0, 9·sin(2πt/7.5))` × `scale(1 − 0.030·(0.5−0.5cos(2πt/5.3)))`。
  同一相位 = 整个构图作为整体在动，是一次"镜头呼吸"，不会各元素各自漂移导致构图散架；
  两个周期（7.5 / 5.3）互质，避免同时到达折返点而让某一帧速度归零。
- **实现要点**（否则会出 bug）：`seek()` 里必须按 **清空 transform → updater 写基础值 →
  统一追加呼吸** 三步走。若直接append，那些自己**不写 transform** 的元素会把上一帧的
  残留一路叠加下去。
- **安全约束**：缩放恒 ≤ 1（只向内收），纵向 ≤ ±9px，**横向取 0** ——
  ep01 全片墨迹左界 x=101、安全区左界 x=100，只剩 1px，横向一动就出界。

### M-46 分镜写了的动作，代码里可能根本没实现 —— 要回头逐条核
- **现象**：ep01 分镜上写着"亮起加号 → **闪烁三次** → 裂开"，代码里只有"亮起 → 裂开"，
  中间 3.6s 完全静止（0.129 级差）。同理"一笔，两笔，三笔"三竖是**同时**出现的，
  并没有"一笔一笔写下去"。
- **规则**：交付前把分镜的动词逐条对照代码。补上的实现：
  加号三次闪烁（周期 0.62s）+ 持续呼吸；三竖用 `stroke-dashoffset` 由满长收到 0 逐笔写出
  （线长从各自的 `y1/y2` 算，不写死常数）。

### M-47 叙事要求"动作"的拍，就得给**真动画**，缓速运镜救不了
- **现象**：第 4.3 句旁白是"圆锥按下去，留下一个楔形。圆球按下去，留下一个圆点。"
  但陶筹早在 `mk(4,2)+0.5` 就退场了 —— **讲动作的时候画面上已经没有动作主体**，
  整句 3.76s 零变化。
- **对策**：把压印拆成**逐枚**执行 —— 第 i 枚在 `PR[i]` 起"下压 0.40s → 停 0.20s → 抬起 0.45s"，
  三枚分别挂到"他把陶筹直接按在湿泥板上"与"圆锥按下去…圆球按下去…"两句上；
  印记比对应那枚的下压晚 0.38s 出现（`im.children[j]` 与 `src.children[i]` 顺序一致，可一一对上）。
- **规则**：`<g>` 内多个同类物件要用 `children[i].setAttribute('transform'/'opacity', …)`
  分别驱动，不要只给整个 `<g>` 一个不透明度。

### M-48 两块**几何上不可能同框**时，中间那段只能"阶跃 + 位移"，不能做透明度斜坡
- **现象**：幕6 升维大字（y 620-914）与支撑句 a6-bij(340-860) / a6-bij2(810-925) 互相压住，
  中间的 925-1030 空带只有 105px，放不下 294px 的三行大字。
  · 两块斜坡重叠 → 交界处都半透明，叠成乱字（留证 `verify/zoom_t192.12.png`）；
  · 两块斜坡错开 → 出现"上一块已淡到 0.08、下一块还没升起来"的暗带（实测该帧峰值亮度 20）。
- **规则**：让支撑块提前归零，主块在那一刻 **直接 `opacity = 1`**，入场感全部交给
  `translateY(24→0) + scale(0.97→1)`。这是一次"落点"，不是一次"溶解"。
- **亮度担保**：落点那一刻要确保还有别的元素是 o=1 —— ep01 里 a6-live(1080-1135) 与
  a6-pyth(1180-1235) 在大字下方、无空间冲突，正好承担这个角色。

### M-49 徽标类角标在交叉溶解里会重影 —— 同拍只让"占优的那张图"出示
- **现象**：幕2 神庙 → 祭司 → 火光脸 是照片交叉溶解，三张卡的 `.tag`（"示意"角标）都在
  同一个角（`right:14px;bottom:12px`），溶解期间两个「示意」同时可见、错开 6-8px，
  读成重影 —— QC-24 实测 t=33.50-33.96 重叠 60%、t=36.92-37.21 重叠 33%。
- **对策**：给三张图的角标各一个 id，在**该幕最后一个** updater 里读三张图的
  `style.opacity`，只给最大的那张 `opacity = 1`、其余 `0`。角标是 `.shotwrap` 的子节点，
  父元素的不透明度照常乘上去，所以稳定态的角标亮度不受影响（已逐帧目视确认可读）。

### M-50 "记分牌/台账"里的数字是新的错误源 —— 事实更正必须三处同改
- **现象**：`FACTS.md` 早就把"29 道刻痕"标成**误传**（那是勒邦博骨，不是伊尚戈骨），

## H. ep02 新增（2026-10-16，四门联调期）

### M-58 ★ `JSON.stringify(NaN) → null` 会击穿一切"可见性"判据
QC-21-D 把元素快照序列化传回 Node 侧比较签名。无 inline opacity 的元素，
序列化后 opacity 字段是 `null`；而 **`isNaN(null) === false`**（null 被强转成 0，
0 不是 NaN）→ 三处 `vis()` 判据全部把 null 当成"可见"，A 方向全元素误报"可见 从未"、
B 方向误报"全程在动"。
**规则**：凡是经 JSON 序列化的数值字段，判空前必须同时查 `undefined / null / isNaN`
三项，写成 `(v === undefined || v === null || isNaN(v))`。别只查 isNaN。

签名（sig）也漏过三类盲区：style.transform 之外的**自身属性**（cx/cy/r/d/fill/opacity）、
**textContent**（大字换数字 = 运动）、**子节点** transform/opacity/stroke-dashoffset。
三者不同时扩展，运动门就存在"看不见的动作"。sig 应扩展为：
`style.opacity + style.transform + 自身几何/填充属性 + textContent + 子节点关键属性`。

### M-59 两个 QC 门不能共用同一个 chrome user-data-dir
qc21d 与 qc24 同时跑，各自 spawn chrome-headless-shell 指向同一 `chrome_tmp_*`
目录 → 互踩 profile，一个门吃掉另一个的进程，表现是"无故超时/连接失败"。
**规则**：每个门/每次调试用独立 profile 目录（`chrome_tmp_qc24`、`chrome_tmp_dbg5`…）。
孤儿进程经 Python subprocess 调 `taskkill /F /PID` 清理（Git Bash 会把 `/F` 转义掉）。

### M-60 `vis()` 的淡出起点是 `outAt + OUT_HOLD`，不是 `outAt`
交叉溶解的两条曲线在**中点相交**，不是在 outAt 相交。按 outAt 估"退场完成"，
会把后一个元素的入场排进前一个元素还没消失的区间 → QC-24 边界帧。
**规则**：排时序时用 `outAt + hold + outDur` 当作"真正归零时刻"；保守做法是
把后元素入场推到前元素归零之后（ep02 有 4 处这么改）。但注意——

### M-61 ★ 空场（QC-23）的正解是"交叉溶解填平"，不是"一味推迟入场"
修两段近黑场时第一轮犯错：只把后元素入场提前/退场推迟，结果
① 后元素（分蛋糕图）到句 2 才出现，过渡句 4.7s 全黑；
② 链条退场推得太晚，第 5 个节点（1793）的点亮时间落在容器归零之后——
**这个节点从来没被看见过**（设计 bug，不是渲染 bug）。
**正解**：空场发生在"前元素归零 → 后元素可见"的间隙，判据是
**任意时刻主区至少一方有效不透明 ≥0.45（峰值亮度 ≈ 7+0.45×184 ≈ 90 > 交付档 60）**。
做法是让两元素做 0.4s 交叉溶解（淡出窗 [T, T+0.40] 与淡入窗 [T+0.05, T+0.45]）。
前提是**两者文本墨迹零相交**（QC-24 只量文本墨迹，SVG 图形相交不判）——
hand2 大字 y460–590 / 提示词 y1190–1230，蛋糕标题 y345–390，几何上天然分离，
交叉溶解对 QC-24 透明。若文本墨迹也相交，才必须用 M-48 的"阶跃+位移"。
**通用排查顺序**：先画出两元素的文本墨迹包围盒，相交 → 推迟入场（M-60）；
不相交 → 交叉溶解填平（本条）。

### M-62 mux 的 `-shortest` 会吞掉 HTML 尾部留白帧（ep03 实踩）
渲染总时长 = `getDuration()` = **音频总时长 + tail_pad**（HTML 剧本里尾部留白是设计，
`final_mix.mp3` **不含**这段静音）。mux 命令若带 `-shortest`，ffmpeg 按音频流截视频，
**末尾 32 帧（1.3s 结尾定格）被静默丢弃**，成片帧数 = 渲染帧数 − tail×fps。
ep03 表现：渲染 5552 帧，mp4 只有 5520 帧 / 230.0s，结尾"下一集"画面在最后 1.3s 才定格。
**规则**：① mux 不用 `-shortest`（尾部留白本就设计为静音，视频流最长即可）；
② **交付前必须跑 `ffprobe -count_frames`，与渲染帧数逐帧对账**（帧数不等 = 没合成完）。

### M-63 交叉溶解期的文本重叠：优先"让文本晚于容器入场"，别挪位置
ep03 修 QC-24「差 8 标签 × Wynn 舞台字幕」重叠时先选了位移（舞台标题 y 80→112 下移 32px），
结果标题框落进**比值标注「8 vs 16 / 16 vs 24」**的包围盒——修好一对、撞上第三元素，
两处重叠换成另两处（maxOverlap 32%→47%）。
**根因**：一个容器里往往上上下下排满了别的元素的标注，"让开"只是平移问题。
**正解**：容器（SVG 背景/舞台）按时序正常交叉溶解，**把容器内最上方那条文本单独排
晚 0.5–0.7s 淡入**——等对面元素归零（opacity < 0.35）它才出现，几何一个像素都不用动。
前提：晚入文本自身要有 ≥0.5s 的静止平台（QC-21-D B 项天然满足）。
判对面"归零"时刻用 M-60 的 `outAt + hold + outDur` 推到 opacity<0.35 再加 0.1s 余量。

## C. 视觉与运动（ep01 第四、五轮，2026-10-17/18 用户反馈后新增）

### M-12 AI 插画全出血铺底，必须按「上映射安全区」约束构图
- **现象**：ep01 第四轮把 6 个背景照片换成 AI 插画全出血铺底，QC-21A 首扫 **3495 帧越界**（右界为主）。生成闸明明测过"外缘 40px 均亮 ≤80"还是漏。

### M-13 火光层四连败：光滑周期函数不可能保证「任意半秒都在动」
- **现象**：ep01 静态背景后 QC-25c 回退到 111 段 DEAD、65 段带旁白。加火光层后仍不过：amp 0.30 太弱；补光心漂移+慢呼吸后 t=156.5–157.0 三正弦同时贴近极小值（Δlum=8<10）；换三角波又被三正弦对消（Δfl_op=0.004）。
- **根因**：QC-25c 比的是 **F(t) 与 F(t−0.5s) 两个端点**，不看窗口内极值。任何光滑周期函数必存在端点差≈0 的 0.5s 窗口；多频相加只能降概率。**唯一结构保证：周期 1.0s 的硬锯齿**（任意 0.5s 窗口端点差恰为量程 0.5）。
- **结局**：用户看到火光 1Hz 起伏后明确否决——「不需要视频中间有一个光源，不需要火光每秒一次的明暗起伏，更不需要任意半秒内都必须动」。**QC-25c「有声必动」门自此作废**（用户第 5 点原话留档）。
- **规则**：运动验收只做语义双向审计（该动的动 / 不该动的不动，见 M-16）；**再也不要用"光"当全局动源去凑门**。

### M-14 亮内容上暖光 Δlum 小——把插画改暗比调光参数有效
- **现象**：act7 运动余量只剩 0.306%（阈值 0.30%）——hand_joints 插画米白布面铺得宽（dark_frac 0.729），是 6 张里最亮的。

- **规则**：运动/对比度不够时，**先把插画改暗**（提示词收紧亮区面积 + 生成闸 dark_frac ≥0.88），再考虑调光。ep01 重生成 dark 0.729→0.955 后余量到 3.131%（10 倍）。

### M-17 环境坑三则（2026-10-18 实测）

- **现象**：相邻两卡在**同一区域前后交替**（旧卡退场与新卡入场时间重叠），bbox 必然相交 → QC-26 FAIL，常伴 QC-24。
- **错误解法**：缩短新卡入场窗口 → 中间出现"两块都没到"的真空 → QC-23b 空屏门直接挂。
- **正解**：**空间错开、时间照旧交叠**。旧卡退场 `translateY` 下沉 40–70px；新卡入场从上方 −120~−130px 滑回 0（1.0–1.2s）。重叠时刻两者已不在同一水平带，bbox 不再相交，QC-23b 仍 0 段。
- **参数**：下沉 40px 配 1.0s 够用；入场元素 >400px 高或重叠 >1s 时用 130px + 1.2s。**必须按"重叠时刻的实际剩余位移"验算**——ep05 首版 130px/0.6s 在重叠时刻只剩 22px，等于没躲开。
- **实测**：ep05 用此法 7 处 → QC-26 四轮收敛 `FAIL=0`，QC-24 从 5 对降到 **0 对**。

### M-76 ★ 拍表必须实测：推算 onset 会差 3.6 秒，制造 0.000% 假 FAIL
- **现象**：按 `mk(5,5)≈161.84` 推算节点点亮时刻，取 `t=162.2` 采样 → 帧差 0.000% → 判"该动没动" FAIL。实际该节点在 **158.33–159.10** 就完成点亮（早 3.6s）。
- **根因**：`mk()` 给的是**句起点**，元素动画可能由句内子事件（逐节点点亮 / 逐格填色 / flash 步进）驱动，真实 onset 由代码时间常数决定，不是句起点。
- **正确流程（三步不可跳）**：① **先逐帧扫真 onset**（点状元素用「区域亮像素数 > N」扫描跳变帧）② **再定采样窗口**（必须**跨在 onset ±0.25s**，不能落段内）③ **最后写进审计表**，docstring 注明"推算 X / 实测 Y / 差 Z 秒"。
- **附带坑**：细线要用**窄带分母**。数轴线身只占 y767–786，用整屏 region 分母稀释成 0.291% 判 FAIL；收窄到 y760–795 后实测 1.229% PASS。

### M-77 ★ QC-26 FAIL 的三时刻像素分流（判定真假，别盲修）
- **判据**：取 bbox 交集区，测三个时刻墨迹像素数 `A 单独` / `B 单独` / `重叠`；`base = max(A,B)`，`增量 = 重叠/base − 1`。
  - **≤15% → 假告警**（bbox 虚高 / 同卡父子相邻 / 不增量）→ 不动代码，进 GHOST 白名单
  - **15–35% → 灰区**，目视关键帧再定
  - **≥35% → 真压字**，修（位移 > 时序 > 版面，这个优先级别反）
- **阈值必须双档**：`62`（捕 0.4 opacity 半透明文字，亮度≈98）与 `110`（实墨迹）。只用 110 会漏掉半透明层，A/B 全区统计为 0 → 误判"不增量"。
- **实测**：ep05 首扫 7 条 FAIL → 分流后 **3 真 4 假**，只修了 3 条真的（连同位移修复共 7 处）。
- **脚本**：`_audit/_ep05_pixelprobe.py`（CASES 表逐条 `label / t_ab / A_box / B_box / t_a_only / t_b_only`）。

### M-78 字幕节奏是完播率的隐性杀手（v6 立项依据）
- **实测欠账**：ep03 有 **9 条字幕超过 6s**（最长 7.9s / 48 字），ep02 有一条 **10.2s**，ep01 最长单条 44 字。ep05 用 `qc28_subpacing.py` 量：**19/68 条超 22 字、15/68 条超 4.5s**。
- **为什么是杀手**：一条字幕停 6–10 秒 = 观众有充足时间读完 → "信息已收完" → 划走。4.5s 是一条硬线。
- **规则**：单条 ≤22 字、≤4.5s；22 字 / 4.5s = 4.9 字/秒，正好落在 1.12–1.18 倍速中文的正常区间，不必牺牲语速。

### M-84 ★ JPEG 帧序列编码必须加 `-color_range tv`，否则五集全是 full-range
- **现象（2026-10-19 首次跑 `epcheck.py` 发现）**：ep01–05 成片 `ffprobe` 全部是 `pix_fmt=yuvj420p` / `color_range=pc`，而五集发布文档里都写着"yuv420p"——**文档与实物不符，且是系统性缺陷，不是某一集的手滑**。
- **根因**：渲染器输出的是 JPEG 帧序列，**JPEG 是 full-range（pc）**，ffmpeg 读 `frame_%06d.jpg` 时把 full-range 标记原样继承到输出，即使命令里写了 `-pix_fmt yuv420p` 也只会变成 `yuvj420p`（j = full range 标记）。
- **后果**：一部分播放器 / 平台转码按 limited range（tv）解读 → **深色发灰、对比度下降、渐变底的层次被压平**。对 v5 的深色渐变基底影响尤其明显（本该是深蓝近黑，被解成中灰）。
- **修法（编码命令加一行）**：
  ```
  -color_range tv -colorspace bt709 -color_primaries bt709 -color_trc bt709
  ```
  或在滤镜链里显式收敛：`-vf "scale=in_range=full:out_range=tv"`。二者取其一，**不要只写 `-pix_fmt yuv420p`**。
- **验证**：`ffprobe -select_streams v:0 -show_entries stream=pix_fmt,color_range -of csv=p=0 成片.mp4` 必须输出 `yuv420p,tv`。
- **代价**：重编码（不能 `-c:v copy`），5779 帧约 1–2 分钟／集，**不需要重渲染**。
- **门**：`epcheck.py` CK-10 会直接拦，并在报告里点明"JPEG full-range 遗留"。
