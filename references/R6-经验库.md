# R6 · 经验库

> **格式**：现象 → 根因 → 规则。遇到怪问题先在这里 Ctrl+F 搜现象。
> 本文件只收**可复现、有根因、能写成规则**的条目；一次性偶发问题不收。

---

## 一、结构与方法

### 1. 结构不能照搬其他品类

**现象**：把做读书号/口播号的稿子结构直接套到知识讲解视频上，完播率崩。
**根因**：口播靠信息密度，讲解靠**悬念密度**；前者是"给你很多"，
后者是"先不给你，再给你"。
**规则**：知识讲解必须有"困局 → 造物"这段缺口。没有缺口就没有悬念，
没有悬念，信息越密越劝退。

### 2. 传说必须标注，不许当事实讲

**现象**：为了故事好听，把一个流传广但无据的说法当事实写进旁白。
**根因**：AI 检索时会把"网上到处都在说"当成"史实"。
**规则**：T3 级（传说/轶事）必须**配音与画面双标**——旁白说"传说"，
画面也有视觉标记。只标一处不算标。

### 3. 故事必须有镜头，不能只写在文案里

**现象**：脚本写得很动人，成片是"大字 + 旁白"，观众说"像在听播客"。
**根因**：把"叙事"理解成了"文字叙事"，没有转成分镜。
**规则**：每一句台词都要能回答"这一刻画面在发生什么"。
答不出的句子，要么删，要么补镜头。

### 4. 抽象句必须有画面承接

**现象**：旁白讲"这其实是一种映射关系"，画面是一张无关的氛围图。
**根因**：抽象句没有指定镜头类型。
**规则**：抽象句**必须落在 SYM 或 SCHEMA 镜头上**（R2 §4.3）。
不能挂在实际物体的镜头上——观众会觉得配音和画面在各说各的。

### 5. 升维句不能是总结

**现象**：结尾写"所以，这个故事告诉我们坚持很重要"。
**根因**：把"收束"误当成"总结"。
**规则**：升维句单独拎出来读，**若只是本集内容总结 → 不合格**。
它必须换一个维度（尺度/视角/时间/概念/身份/反身/文明），让人看见"更大的东西"。

### 6. 单集赌注撑不起长系列

**现象**：系列做到十几集，每集都在"讲一个新知识"，观众不追更。
**根因**：缺少贯穿全系列的悬念。
**规则**：做 ≥10 集的系列，必须设一个**核心诘问**（二分问题），
每集记一分，终章揭晓。单集赌注只能解决单条视频的留存。

### 7. "活泼"靠文本工程，不靠音色卖俏

**现象**：为了让片子显得轻松，换了很"活泼"的 AI 音色，结果显得廉价。
**根因**：把语气问题当成了音色问题。
**规则**：语速、停顿、断句、用词决定"好听"；音色只决定"是谁在说"。
**幽默靠文本，不靠音色演**。

### 8. 通俗化是顺序问题，不是词汇问题

**现象**：把"函数"改成"一种对应关系"，观众还是不懂。
**根因**：只换了词，没有给经验。
**规则**：必须按 **身体锚 → 可数锚 → 图像锚 → 名字锚** 的顺序（R3 §6）。
**先在观众身上找到一个已有的经验，再给它命名。**

## 二、素材与视觉

### 9. 真实人物不用 AI 造脸

**现象**：用图生图生成历史人物肖像，观众一眼看出"不像"，或者像某个明星。
**根因**：人格权 + 误导双重风险。
**规则**：用公有领域图像 / 无脸剪影 / SVG 重绘。**不要生成可辨认的脸。**

### 10. AI 素材不得作为证据

**现象**：片中用一个 AI 生成的"古代场景"当作史实配图。
**根因**：把"气氛素材"当成了"资料"。
**规则**：AI 素材只当示意/气氛，披露写在发布文档的授权节。
**画面内不打「示意」角标**（角标会破坏观感），但文档必须写清。

### 11. AI 素材风格会漂

**现象**：同一集里两张 AI 图，一张偏写实、一张偏插画。
**根因**：每次生成都重新随机，提示词不够硬。
**规则**：① 提示词里写死"单一主色 + 无渐变 + 无文字"；
② 每张落盘即过数值风格闸（暗部占比 / 外缘亮度 / 主色像素 / **量化色数 ≤400**）；
③ 不达标重试 ≤2 次，还不达标就换构图。

### 12. 量化色数是判"扁平"最硬的指标

**现象**：生成的图看起来像插画，铺到画面里却"脏"。
**根因**：其实是照片或带大量渐变，不是扁平色块。
**规则**：把图量化到 32 级后统计色数，**≤400 才算扁平**（照片是几千）。
这条比肉眼看可靠得多。

### 13. 全出血插画会毁掉可读性

**现象**：插画铺满整屏，文字压上去后看不清。
**根因**：插画的亮度分布不受控，文字没有稳定的对比背景。
**规则**：**背景只允许纯色/渐变，插画一律降级为内容层卡片。**
确需全出血时，必须按安全区映射约束构图（R2 §4.4）。

### 14. 小元素在全屏帧差里会被稀释掉

**现象**：一个 20px 高的线条明明在动，运动审计判"没动"。
**根因**：用整屏做分母，1px 的变化被稀释成 0.29%。
**规则**：小元素必须用 **localized 窄带区域**测帧差，不能用全屏。

### 15. 硬编码颜色会在换底后集体消失

**现象**：换了背景色，页面上的标签、水印直接看不见了。
**根因**：这些颜色是写死的灰，不随配色走。
**规则**：每套配色必须配一张 `grayMap`，把冷灰映射成同色系可见色。
换底之后必须逐元素检查"还在不在"。

### 16. 深色底上的水印要比底"亮"

**现象**：想让水印"若有若无"，用了比底色更深的颜色，结果完全看不见。
**根因**：深色底上"更深"= 更接近黑 = 消失。
**规则**：幽灵水印用**比底亮 8–15%** 的同色系，靠不透明度控制强弱。

## 三、动画与时间轴

### 17. 运动必须有理由（最重要的一条）

**现象**：给全片所有元素加了一个永不停止的"镜头呼吸"，看起来"有生气"。
**根因**：误把"画面在动"当成了"画面有生命"。
**规则**：**只有该动的东西动。** 实物物理 / 运镜 / 叙事动作三类之外一律静止。
**静止可以是正确答案。** 全局呼吸、统一 scale 抖动一律禁止。

### 18. 元素不会自己退场

**现象**：上一拍的元素一直留在画面里，越到后面越满。
**根因**：只写了入场，没写退场。
**规则**：必须建**幕级硬清场表**——每一拍明确列出"这一拍结束时哪些元素必须消失"。
不能指望"后面画的会盖住前面"。

### 19. 同区域的文字必须在时间上互斥

**现象**：两句话的字幕叠在一起。
**根因**：两条 cue 时间重叠，或者文案换了但 cue 没改。
**规则**：同一屏幕位置上的文本，时间区间**不得重叠**。
用脚本检查相邻 cue 的 start/end，不要靠眼睛看。

### 20. 字幕折行必须由宽度反推

**现象**：字幕在某个字上被硬切开，语义断裂。
**根因**：按字数折行，没按实际渲染宽度。
**规则**：用渲染后的实际宽度判断是否需要折行，**折在语义停顿处，不拆词**。

### 21. 每一幕的第一个画面必须早于该幕首句

**现象**：某幕开始，先出现半秒空白字幕，然后画面才来。
**根因**：入场时间按"幕起点"算，但渲染有延迟。
**规则**：幕首元素入场时间必须 **< 该幕第一句的 start**（建议提前 0.1–0.2s）。

### 22. `childNodes` 会混入换行文本节点

**现象**：`seek()` 遍历子节点时静默中断，画面卡在某一帧。
**根因**：HTML 源码里的换行被解析成文本节点，遍历时取到 `undefined`。
**规则**：遍历用 `children`（只有元素节点），不要用 `childNodes`。

### 23. `JSON.stringify(NaN)` 会变成 `null`

**现象**：可见性判据全部失效，门报"全部可见"。
**根因**：`NaN → null`，下游 `>= 0` 判断变 true。
**规则**：所有计算出的数值在写进 JSON 前必须 `Number.isFinite()` 检查。

### 24. 幕末清场必须是淡出，不能瞬时置 0

**现象**：幕与幕交界处出现一帧全黑。
**根因**：上一幕元素被瞬时清掉，下一幕还没入场。
**规则**：清场用 0.2–0.4s 淡出，并保证下一幕首元素**在淡出完成前**已经入场。

### 25. 同框嵌合的两块要"共存后抽走"，不要交叉溶解

**现象**：两块内容互相嵌在对方空隙里，交叉溶解时读不出来。
**根因**：交叉溶解假设两块在空间上互斥，嵌合图不满足。
**规则**：给 `vis()` 传 `hold=0`，等入场块 o=1 后再快速抽走出场块。

### 26. 几何上不可能同框时，只能阶跃 + 位移

**现象**：两块图必须占据同一区域，做透明度斜坡时中间出现"两块都半透明"的糊帧。
**根因**：透明度斜坡的本质是"两块同时存在"。
**规则**：先位移错开，再各自淡入淡出。**不要在同一位置做交叉溶解。**

### 27. `mk()` 的节拍来自 SUBS：cue 可以不上字幕，但不能删

**现象**：删掉一条不上字幕的 cue 后，后面某段动画提前了十几秒。
**根因**：`mk(scene, idx)` 用 `SUBS[scene][idx].start` 取节拍；
删了 cue，索引错位，回落到幕起点。
**规则**：不上字幕用 `"nosub": true` 标记，
**字幕渲染器与 SRT 生成器跳过它，但数据里必须保留。**

### 28. 拍表必须实测，不能推算

**现象**：按 `mk()` 推算动画 onset 是 161.84s，采样 162.2s 帧差 0.000%，判"没动"。
**根因**：`mk()` 给的是**句起点**，元素动画的真实 onset 由句内子事件决定（可能早 3.6s）。
**规则**：**先逐帧扫真 onset，再定采样窗口（跨 onset ±0.25s），最后才写审计表。**
并按"推算值 X / 实测 Y / 差 Z"记进脚本注释。

## 四、渲染与浏览器

### 29. 长渲染一定会崩

**现象**：渲几百帧后 `TargetCloseError`，进程被杀。
**根因**：headless Chrome 长任务内存/句柄泄漏。
**规则**：写 **resume 循环**：每轮跳过已存帧；每轮开始前清理 orphan 进程；
循环上限设 200 轮，跑完检查帧序完整性。

### 30. 断点续渲用 skip-existing，不要从头再来

**规则**：渲染器启动时扫描已有 `frame_%06d.jpg`，
存在则跳过。**8 分钟的渲染不值得重跑。**

### 31. 端口必须每集递增，且要主动 kill

**现象**：第二次渲染报"端口已被占用"。
**根因**：上一轮的 Chrome 没退干净。
**规则**：CDP 端口 = 9431 + 2N，HTTP = 8891 + N；
每轮开始前显式 kill 残留进程。

### 32. 两个质检门不能共用同一个 user-data-dir

**现象**：并行跑两个浏览器任务，互相抢锁，双双失败。
**规则**：每个任务独立的 `--user-data-dir`。

### 33. 调试脚本 spawn 浏览器可能 ENOENT

**现象**：独立写的调试脚本报"找不到可执行文件"，主渲染脚本却正常。
**根因**：某些沙箱只放行已知脚本路径。
**规则**：不要写独立 spawn 脚本，**在现有 `render.js` 里加一个 mode**。

### 34. Chrome 的 CJK 字形栅格跨进程不确定

**现象**：局部重渲后，接缝处有 1 帧字重/位置跳动。
**根因**：不同进程的字形栅格化结果可能有亚像素差异。
**规则**：**成片必须一次性全量渲染。** 局部补渲只用于排查，不用于交付。

### 35. 渲染前先跑 DOM 预筛

**现象**：渲了 8 分钟才发现文字越界，改完再渲 8 分钟。
**根因**：把"能提前查的"放到渲染后查。
**规则**：渲染前用 DOM 实测包围盒做一次预筛（越界/重叠/空容器），
3 分钟能把同类问题一次找全。

### 36. 局部亮度探针先验证，再全渲染

**现象**：改了一处，不确定有没有效果，直接全量渲染。
**规则**：先在目标时间点抽 3–5 帧做探针，确认有效再全渲。

### 37. 只修被量到的问题

**现象**：修 A 幕的问题时顺手"优化"了 B 幕，B 幕反而出新问题。
**规则**：**不要顺手改进没出问题的部分。** 一次改一件事，改完立刻复测。

## 五、音频

### 38. 多数 TTS 不给句级时间戳

**现象**：合成一段音频，无法知道每句从哪里开始。
**根因**：接口只返回整段音频。
**规则**：用 `silencedetect` 反推句级节拍，或用固定速率 + 人工校准。
**不要假设有 SentenceBoundary 字段。**

### 39. 先合音频再改脚本 = 全部重做

**现象**：音频合成完，又改了两句台词，节拍全错。
**规则**：**脚本定稿后才建音频。** 音频建完再改脚本，等于重做。

### 40. 人声电平不能跟着垫乐走

**规则**：人声 +2dB 为基准，垫乐给人声让路（-26dB 以下）。
反过来做（先定垫乐，再把人声压进去）会让旁白永远不够清楚。

### 41. 片头 BGM 必须在 0–1s 达峰

**现象**：片头做了 BGM，但手机外放几乎听不见。
**根因**：起音慢、能量落在低频。
**规则**：**0.0–0.10s 内达峰，主音在 600–2000Hz。**
验收：0–1s 的 RMS 比 2–3s 高 **≥6dB**。

### 42. `-shortest` 会吞掉尾部定格

**现象**：结尾卡一闪而过，观众读不完。
**根因**：音频比画面短，`-shortest` 按音频截断。
**规则**：**不要加 `-shortest`。** 视频比音频长 1.3–3.8s 是设计。

### 43. 编码色域不收敛会发灰

**现象**：深色渐变底在某些播放器上偏灰。
**根因**：JPEG 帧是 full-range，输出变成 `yuvj420p / pc`。
**规则**：必须加 `-color_range tv`，编完 `ffprobe` 确认是 **`yuv420p,tv`**。
这是跨项目最常复发的一个坑。

## 六、质检与验收

### 44. 不说"我看完了每一帧"

**规则**：只说"每帧过了机器判定 + 关键帧与高难段逐张目视"。
一集 4000+ 帧，人眼看完全部是不可能的，说这话等于自曝不可信。

### 45. 机器查不出"难看"和"看不懂"

**规则**：机器管结构（越界/重叠/黑帧/编码），人管感受（切题/气质/易读）。
**两层都要，缺一层就会交付一个有硬伤或没意思的片子。**

### 46. 抽查 ≠ 验证

**现象**：抽了 9 帧都正常，交付后发现某一段全黑。
**规则**：抽查只证明"抽到的没问题"。**必须配合全帧机器判定（QC-21A）。**

### 47. 空画面判据用峰值亮度，不用亮像素计数

**现象**：细线图形被判成"空画面"。
**根因**：细线全不透明时亮像素计数也很低，与真空画面同量级。
**规则**：用**主画面区最大亮度**（阈值 60，严格档 100 双档输出）。
"亮像素计数"会大量误判。

### 48. 量墨迹，不量盒子

**现象**：DOM 报 7 处压字，改完发现 4 处是假的。
**根因**：bbox 虚高（行高、父子同卡、字形相隔 1px）。
**规则**：bbox 只做初筛，**判定必须过三时刻像素分流**（R4 §9.1）：
增量 ≤15% 假告警、≥35% 真压字。

### 49. 交叉溶解期的文本重叠，优先让文本晚入场

**现象**：新旧两张卡在溶解期文字重叠。
**规则**：先调时序（让新文本晚于容器入场），再考虑挪位置。
**动版面是最后手段。**

### 50. 安全区不能拍脑袋

**规则**：每个数字都要说得出来源（哪个平台、哪年、什么机型）。
说不出来就标"经验值"，**不许写成"实测值"**。

### 51. 台账里的数字是新的错误源

**现象**：封面写 168，台账写 29，两者不一致。
**根因**：事实更正时只改了一处。
**规则**：一个数字出现在台账/脚本/封面/口播四处，**更正必须四处同改**。
交付前做一次数字一致性对账。

## 七、流程与环境

### 52. 判断模型/端点是否存在，唯一判据是实机调用

**现象**：检索说某个模型不存在，实际调用成功；或反过来。
**规则**：**不许凭检索下结论。** 未知参数先小样本试一次，看返回。

### 53. API 参数名传错会静默忽略

**现象**：传了 `size`，出图还是默认比例。
**根因**：该接口只认 `ratio`，其余字段被忽略且不报错。
**规则**：第一次调用就**验证输出尺寸**，不要假设参数生效了。

### 54. 大段中文不要直接写进 .py

**现象**：脚本报 `SyntaxError`，看代码没问题。
**根因**：编辑器/工具把全角引号规范化成 ASCII 引号，字符串提前闭合。
**规则**：文案抽到独立 `.md` / `.json` / `.txt`，代码只读文件。

### 55. 删除文件可能静默失败

**现象**：删了目录，脚本回读发现还在。
**根因**：安全删除垫片走了回收站，回收站操作失败即静默不删。
**规则**：用 Python `shutil.rmtree` / `os.remove`，**删完必须回读验证**。

### 56. 批量删帧会被安全垫片拦截

**规则**：删整堆帧前先 `os.rename` 改名留作备份，
渲染器会自动建新目录。**不要逐张删。**

### 57. 同一文件不要并行发多个编辑

**现象**：两次编辑都返回成功，但前一次的内容没了。
**根因**：后写的基于旧快照，静默覆盖。
**规则**：**同一文件的多次编辑必须串行。**

### 58. 程序生成的图必须逐张打开看

**规则**：生成"成功"不等于"正确"。
每张落盘后 Read 一次，确认构图/文字/颜色，再报完成。

### 59. 交付要自动归档，不能等提醒

**规则**：三件套生成完立即归档 + sha256 回读。
**归档后必须回读验证**，不许以"命令没报错"当成功依据。

### 60. 旧帧备份会吃掉硬盘

**规则**：每版备份可能几百 MB 到 1GB。定稿交付后清理，只留最终版。

### 61. 注释里的旧算术是坑

**现象**：改了常量，注释里还写着旧的计算过程，下一个人照着注释算错。
**规则**：改数值时**同步重算注释里的每一处推导**。

### 62. 长句不能只写入场动画

**现象**：一句 6 秒的旁白，画面只有前 0.5 秒有变化，后面 5.5 秒静止。
**根因**：只做了入场。
**规则**：长句要么拆成两条 cue，要么在句内安排一个**有理由的**动作节点。
（注意：不是加无意义呼吸，见第 17 条。）

### 63. 分镜写了的动作，代码里可能根本没实现

**规则**：渲完必须回头**逐条核分镜表**——
每一条"球落下/手指按下/卡片翻面"都要在成片里找到对应帧。
机器门查不出"该发生的事没发生"。

### 64. 叙事要求动作的拍，缓速运镜救不了

**现象**：分镜写"他把印按下去"，代码只做了镜头轻微推近。
**规则**：叙事动作必须是**真动画**（元素位移/形变），运镜是另一回事。

### 65. 两块内容必须同框时，先给空间再给时间

**规则**：见第 26 条。**空间错开优先于时间错开**，因为时间错开会产生空帧。

## 八、怎么用这份经验库

1. **遇到怪问题先搜现象关键词**（"发灰"/"重叠"/"没动"/"崩"）。
2. **新踩的坑按"现象 → 根因 → 规则"三行写**，不要只写结论。
3. **规则必须是可执行的**。"注意画面质量"不是规则；"暗部占比 ≥50%"是。
4. **一条规则只解决一类问题**。如果一条规则要解释三种情况，拆成三条。
