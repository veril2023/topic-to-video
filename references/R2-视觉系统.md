# R2 · 视觉系统

> 这份文档解决一个问题：**画面怎么才能既好看，又不撒谎。**
> 读它的时机：分镜设计、写 HTML 之前。

---

## 4.1 画面资产四级

| 级 | 用途 | 生产工具 |
|---|---|---|
| **L1** | 图形 / 图式 / 符号 / 抽象演示（**默认首选**，SYM/SCHEMA 强制） | 手写内联 SVG |
| **L2** | 人 / 场景 / 气氛（**只以圆角卡片形式出现，不做全出血背景**） | 任意图生图（图生图做角色一致） |
| **L3** | 只用于 人 / 火 / 烟 / 水 / 云 / 光尘 | 任意视频生成模型 |
| **L4** | 实景照片 —— **默认禁用**；确需使用时每集 ≤2 张、高质量、与主题匹配，且须在发布文档说明 | 公有领域 / 授权图库 |

**口诀：人和气氛交给 AI，概念和图式交给 SVG。**

- ⚠️ **真实人物不用 AI 造脸**（人格权 + 误导）→ 公有领域图像 / 无脸剪影 / SVG 重绘。
- ⚠️ **AI 素材不得作为证据**，只能当示意与气氛；披露写在发布文档的授权节。
- ⚠️ **背景层零照片、零全出血插画**：背景只允许纯色/渐变，插画一律降级为内容层卡片。

> 为什么不让插画铺满整屏：一旦铺满，文字就成了"压在画上"，
> 安全区、对比度、可读性三件事会同时失控。卡片化是这三件事的唯一稳定解。

## 4.2 动画实现分级 A0 / A1 / A2

> **判据：画面里这个"动"，如果观众可能把它当成"证据"看，就必须由程序算出来。**

| 级 | 做法 | 用于 | 可核验 |
|---|---|---|---|
| **A0** | SVG/Canvas + 时间轴引擎（默认） | 一切可被精确描述的运动、形变、推进 | ✅ |
| **A1** | 真实方程驱动（重力/阻尼/反应扩散/种群/波） | 物理、生物、经济模型 | ✅ |
| **A2** | AI 视频 | **仅** 人 / 活物 / 火 / 烟 / 水 / 云 / 光尘 | ❌ |

**A2 四条禁令**：
① 不许出现数字/公式/图表/坐标轴；
② 不许展示"精确运动"；
③ 不许作为实物证据；
④ 单段 ≤6s 且必须叠 A0 层。

> **"一颗球滑落" → 用 A1，不调视频 API。**
> AI 的球会漂移、变形、穿模，观众一眼看出来，整集可信度崩。

## 4.2b 运动必须有理由

**这条是设计纪律，不是调参建议。**

> 曾经有一集给全片每个舞台元素都加了一个永不停止的"镜头呼吸"（sin 位移 + scale），
> 理由是"让每一句配音期间画面都有像素变化"。结果被判为不合格：

> "画面在动不是说任何一张照片都必须要动，只有该动的东西要求动。
> 比如被风吹的火焰、高处落下的小球，这些是实物本身的运动；
> 而不是你要求本来应该静止不动的东西也动，比如一根棍子。"

### 判据表

| 运动类型 | 是否允许 | 判据 |
|---|---|---|
| 实物自身物理运动 | ✅ 必须 | 火被风吹、球自由落体、压印下压、刻痕被刻出、水面波纹 |
| 相机运镜（推/拉/摇） | ✅ 允许 | 分镜写了推近意图；**相机在动，物体不动** |
| 叙事动作（写、按、翻、拼装） | ✅ 必须 | 与当句台词同步 |
| **无理由的全局漂移/呼吸** | ❌ **禁止** | 全屏 sin 抖动、所有元素统一 scale 呼吸、"为了过门而让它动" |
| **为凑数给静止元素加动** | ❌ **禁止** | 静止可以是正确答案 |

### 落地手段：`data-motive`

HTML 里给每个元素打标注：

| 标注 | 含义 |
|---|---|
| `data-motive="physics"` | 实物物理 |
| `data-motive="camera"` | 运镜 |
| `data-motive="act"` | 叙事动作 |
| **无标注** | **必须全程静止** |

门按标注校验：有标注的元素在其所属拍内**相邻帧差必须 > 0.02**；
无标注的元素相邻帧差**必须 = 0**。

**写 `data-motive` 之前先在分镜板上写清运动理由，写不出理由的就是无标注。**

## 4.3 叙事分镜层（核心机制）

### 六镜型

| 型 | 全称 | 拍什么 | 强制 |
|---|---|---|---|
| **EST** | 环境 | 空间、时代、氛围 | |
| **ACT** | 动作 | 人在做什么 | |
| **CU-prop** | 道具特写 | 手部、器物、细节 | |
| **CU-face** | 表情 | 情绪、决断 | |
| **SYM** | 象征 | 抽象概念的视觉隐喻 | **必须 L1** |
| **SCHEMA** | 图式 | 结构、流程、关系图 | **必须 L1** |

### 七条硬规矩

- **R1** 每个故事幕拆 **4–8 镜**，每镜 **2.5–8s**。
- **R2** 相邻镜头**不得同型**。
- **R3** 每幕一个**道具锚**（可触摸实物），全集至少回闪一次。
- **R4** **抽象句必须落在 SYM 或 SCHEMA 上**，不能挂在实际物体的镜头上。
- **R5** 每一镜必须能回答"**这一格你能看见什么？**"——答不出就是没设计。
- **R6** 元素入场时间必须来自对应句的 `mk(scene, idx)`；**`mk()` 的节拍取自 SUBS cue 的 `start`**。
  所以 **cue 可以"不上字幕"但绝不能从数据里删掉**——改用 `"nosub": true` 标记，
  字幕渲染器与 SRT 生成器跳过该 cue，而 `mk()` 照常取到节拍。
  （历史教训：直接删 cue 会让 `mk(7,5)` 回落到幕起点，预告提前 13s 入场。）
- **R7** **分镜板先出**，不过门不许写一行动画代码。

### 素材分工

| 内容 | 用什么 |
|---|---|
| 人物 / 气氛 | L2 / L3 |
| 真实文物 / 场景 | L4（须授权） |
| 概念道具 | L1 |
| 隐喻图式 | **L1 一律** |

## 4.4 AI 素材风格护栏

> 目的：让不同批次生成的图**看起来像同一个人做的**。风格漂移是 AI 素材最大的坑。

### 第一级 · 扁平知识卡片风（默认）

```
flat vector illustration, modern knowledge-card editorial style, bold simple shapes
with minimal shading, clean flat color fields, deep navy-charcoal background (#141824),
a single warm <ACCENT> key light as the only accent color, muted desaturated
blue-gray secondary tones, confident geometric composition, no gradients on shapes,
no text, no watermark, no signature, no modern objects, no readable human faces
```

> `<ACCENT>` 换成你 `brand.json` 里的 `accent`。主色只有一个，这是风格统一的关键。

**数值风格闸（每张落盘即检，不达标重试 ≤2 次）**：

| # | 判据 | 抓什么 |
|---|---|---|
| ① | 暗部（<60）占比 ≥50% | 画面太亮，不是深色卡片风 |
| ② | 外缘 40px 均亮 ≤80 | 边缘漏光，铺底会与背景打架 |
| ③ | 暖光像素 ≥0.5% | 主色缺失，整张图没有视觉焦点 |
| ④ | **量化色数（32 级）≤400** | 照片是几千色；这条是"扁平"的硬证据 |

> ④ 是最有用的一条。它能把"看起来像插画其实是照片"的图筛掉。

### 第二级 · 氛围风（需要电影感时才用，默认不用）

```
vertical 9:16, cinematic still, deep near-black background (#07080C),
single warm key light, heavy vignette, muted desaturated palette,
subtle 35mm film grain, museum-documentary mood,
no text, no watermark, no signature, no modern objects
```

### 全出血铺底的安全区映射闸（仅回退到全出血时启用）

插画若全出血铺底，736×1312 以 cover 铺到 1080×1920 后，
安全区 x60–890 / y220–1500 **只对应图像坐标 x[41,607] / y[152,1023]**——
生成闸只测图像外缘会漏。

**硬闸**：亮像素（>75）包围盒必须落在图像 **x[50,590] / y[160,1000]**。
（卡片场景另加径向 mask 兜底，用不上这条。）

### 后处理（每张必过）

1. 暗部压到背景色（避免卡片与背景之间出现一条灰边）
2. 高光染主色（保证全片只有一个 accent）
3. 包 1.5px `rgba(245,240,230,.10)` 描边圆角卡面

### 分辨率

| 用途 | 生成比例 | 实测出图 |
|---|---|---|
| 卡片槽位 | `3:4` | 864×1152 |
| 全出血（不推荐） | `9:16` | 736×1312 |

**不要上采样。** 上采样的模糊会被压缩后放大，比原生小图更难看。

## 4.5 配色与安全区

### 配色（全部来自 `brand.json`，下面是默认值）

```
背景   线性渐变，见 §4.6（不是纯色；禁止纯黑铺满全屏）
卡片面  #141824  ｜ 次级面 #1A1D2A
主文字  #F5F0E6    次文字 rgba(245,240,230,.55)    弱文字 rgba(245,240,230,.38)
描边    1.5px rgba(245,240,230,.10)
accent  单色，全片只用这一个（默认 #E8A33D）
```

**字体**：中文正文 苹方 / 微软雅黑；金句 宋体 / STSong。
**公式与关键数据一律程序排版**（SVG 画根号横线、表格画数据），禁止字符堆叠、禁止截图贴图。

### 安全区：x 60–890 / y 220–1500（1080×1920）

四平台 UI 遮挡的并集，**推导如下（数据性质必须如实标注）**：

| 平台 | 上 | 下 | 右 | 左 | 来源性质 |
|---|---|---|---|---|---|
| 抖音 | 192 | 422 | 194 | 54 | 第三方实测整理（2024） |
| 快手 | 192 | 422 | 194 | 54 | 同上 |
| 视频号 | 230 | 384 | 162 | 54 | 第三方经验值，无测量说明 |
| 小红书 | 230 | 307 | 65 | 65 | 第三方设计经验值，基于 3:4 画布 |

**四平台没有一个是官方数值，也未经真机逐机型验证。** 所以：

- 文档里**不许**把估算值写成"实测值"；
- 发布前建议做一次真机截图校准（用目标机型、目标 App 版本各截一张，量实际遮挡）；
- **决定上下界的是抖音/快手**（底部遮挡最大），**决定左右界的是抖音/快手 + 小红书**。

> ⚠️ **安全区 ≠ 内容层起始线**。
> 安全区是"平台 UI 不会挡到的最大范围"；内容层起始线是"避开自家角标的内缩线"。
> 角标放大后墨迹到 y277 → **所有卡片/图形/赌注带的上沿一律 `y ≥ 300`**。
> 两者别混：安全区上界 y220 不变，内容层从 y300 开始。

### 字幕带

- 基线 **y 1370–1460**，落在安全区内；**下沿硬上限 y 1500**。
- 再往下（y > 1700）会被平台 UI 完全遮挡。

### 字幕节奏硬约束（QC-28 判据）

| 项 | 上限 | 说明 |
|---|---|---|
| 单条**总字数** | **≤22 字** | 超过必须拆成两条 cue（拆点在语义停顿处，不拆词） |
| 单条**停留时长** | **≤4.5s** | 超过必须拆条。停留 6s 以上等于告诉观众"信息收完了，可以划走" |
| 单**行**字数 | ≤19 字 | 排版物理极限；22 字可分两行，19 字是一行放得下的上限 |
| 阅读速度 | **3.5–9.0 字/秒** | 中文旁白（约 1.1–1.2 倍速）实测 5–7 字/秒是正常的 |

> **这条最容易欠账**：写脚本时觉得"这句要讲清楚"，渲完发现单条 7–10 秒。
> **在脚本阶段就拆**，不要指望渲染后补。

### 封面裁切比正片更狠

核心文字与主体放 **y 220–1300（上 2/3）**。
视频号半屏浏览约 3:4、小红书笔记首图主流 3:4，都会切掉底部——
**下 1/3 只放辅助信息或不放**。

## 4.6 视觉基底

### 背景

**深色垂直渐变**，不用纯黑也不用照片。默认（`brand.json` 的 `bg_gradient`）：

```css
linear-gradient(180deg, #0D1118 0%, #1A2130 100%)
```

写在 `#stage` 上，**全片静态**：无星点、无暗角、无任何背景层元素。
（背景一动，所有元素的对比度都在变，可读性随之失控。）

### 常驻角标（左上）

```
logo  57px  +  系列名单行 33px / 700
left: 60px;  top: 220px;  0.05s 淡入后全片可见
```

**连带硬约束（必须同步改，否则压字）**：
角标墨迹范围到 **y 220–277**，因此
**内容层上沿从 `y ≥ 260` 下移到 `y ≥ 300`**。所有卡片、图形、赌注带一律不得进入 `y < 300`。

> **别搞混两个 logo**：左上角是**常驻小角标**（全片在屏，要"随时可辨"）；
> 片头里那个**居中大 logo** 是另一回事（要"1 秒内塞得下"，所以更小）。

### 集标（右上，做系列时）

```
EP.06           22px / 700，主色，字距 .12em
<本集主题简写>   16px，次文字色，≤10 字
right: 60px;  top: 220px;  与左上角标同基线
```

- 与左上角标同行时**水平净空 ≥40px**。
- 集名超 10 字改台账里的 4–6 字简写。
- **片头右下角的集号微标取消**，统一由右上角集标承担（避免同屏两个集号）。

### 片头版式（≤1.0s）

**品牌信息保留全部，只压时间。**

| 时间 | 事件 |
|---|---|
| 0.00s | **片头 BGM 起** + 「唰」飞入音效（0.12s 落点） |
| 0.00–0.28s | 品牌卡整体从下方 40px 上浮 + 淡入（ease-out） |
| 0.12–0.55s | 大 logo 落定（**180px**）+ 三行大字错峰 0.06s 依次淡入 |
| 0.55–1.00s | **全要素定格 0.45s**（必须有，否则一闪而过等于没显示） |
| 1.00s | 品牌卡退场，幕 1 入场；**BGM 继续，1.0–3.5s 内淡出到垫乐电平** |

尺寸参考（在 1s 内放下且不挤）：大 logo 180px；三行大字 66 / 20 / 36px
（第一行系列名 66px 主色；第二行口号 20px；第三行「第 0N 集 · 主题」36px 主色）+ 细线圆点分隔 y≈940。

> **1.0s 是上限不是目标值**；能压到 0.8s 就压，省下的都还给内容。
> **但定格段不得少于 0.30s。**

### 封面（3:4）

- **尺寸 1200×1600**（3:4），程序渲染（HTML/CSS/SVG，零成本，数据驱动，改配置即出新集）
- **结构**：左上徽章（logo + 系列名 + 副标）｜中央集名 + 上小标｜钩子胶囊｜
  底部每集专属 SVG 符号｜底口号
- **背景**：沿用 `brand.json` 的渐变与 accent，保持全系列一致
- 核心信息压在 **上 2/3（y 220–1300）**，下 1/3 只放辅助元素

### 结尾卡（幕 7）

两拍揭示：

- **拍 1** = 深色悬念卡（问题 + 细线圆点分隔 + 答案主色）+ **静态暖聚光**（椭圆 radial-gradient）
- **拍 2** = 主色渐变主卡（渐变底 + 顶部高光 inset + 投影）含胶囊徽章「下一集」+ 标题 + 集号副标 + 系列落款

**三条纪律**：

1. **预告构图的图形必须收在 y < 1350**（字幕带从 y1358 起）。
2. **同句双显禁令**：预告卡自带全部文字时，**字幕带对应 cue 退场**——
   否则同一句话出现两遍，画面混乱。落地方式：给末句 cue 加 `"nosub": true`
   （保留在 SUBS 里供 `mk()` 取节拍），字幕渲染循环与 SRT 生成同步跳过。
   **不要用删 cue / 改 cue end 的方式实现。**
3. **退场前移**：上一拍的退场起点要比下一拍入场早 0.5–0.7s 开始淡出，
   否则交叉溶解会造成 1–4 帧几何重叠（QC-26 报 FAIL）。
