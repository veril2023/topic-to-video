# R5 · 生产流程（15 步）

> 这份文档是**操作手册**：每一步做什么、产出什么文件、过哪道门。
> 读它的时机：开工时、渲染时、不知道下一步干什么时。

## 10. 标准流程

| # | 步骤 | 产出 | 门 |
|---|---|---|---|
| 1 | 选题分析（9 问） | 选题结论（做/不做） | QC-0 |
| 2 | 观众 / 平台 / **结构**确认 | 输入契约 1–5 项（结构见 `structures/README.md`） | — |
| 3 | 单集目标定义（**先写结尾那句，再写开头**） | 一句话目标 | — |
| 4 | 大纲（**选定结构的幕表** + 变体 + 落点型） | 大纲表（含兑现幕标注） | 结构不匹配 → 回步骤 2 |
| 5 | 查重 | 查重记录 | QC-1 |
| 6a | 检索稿 | 资料清单 | — |
| 6b | 事实台账 + 改写稿 | `FACTS.md` + 脚本 | QC-20 → QC-2 |
| 7 | **开场三件套** | 钩子六句 + 赌注句 + 拆好的字幕 | **QC-27 / QC-28** |
| 8 | 分镜设计 → **分镜板 SVG** | 分镜板 | QC-17 |
| 9 | 素材预处理 | 图片/插画（含风格闸） | QC-15 / QC-18 |
| 10 | 音频构建 | `final_mix.mp3` | QC-3 / QC-5 |
| 11 | HTML 动画（句级驱动） | `standalone.html` + `timeline.js` | QC-4 / QC-11 / QC-13 |
| 12 | probe → 全量渲染 → 编码 | `frames/` + `.mp4` | QC-9 |
| 13 | 质检门全跑 | 报告 | QC-0~28 |
| 14 | 逐帧验收 + 通俗化 + 空画面 + 重叠 + **体检** | `epcheck` 报告 | QC-21/22/23/24/26 + **QC-29** |
| 15 | 交付 + 归档 + 复盘回写 | 三件套 + `SERIES.md` 更新 | QC-7/8/16/19 |

### 第 2 步为什么现在要顺带定结构

过去"七幕"是唯一选项，现在不是。**结构错了，第 4 步的大纲会空**——最典型的是第 3 幕只能写
"让我们来看看"，第 4 幕说不出"观众此刻看到的具体东西是什么"。

30 秒判断法：**这集里"造出来的那个东西"长什么样？**

- 说得出来 → `seven-act`，往下走，不要多花时间。
- 说不出来，但有个东西崩了/被推翻了 → 读 `structures/README.md`，试崩解类结构。
- 两头都不是 → 先试 `seven-act` 的 B 变体（思想实验），仍不成立就照 `structures/_template.md` 自建。

### 第 3 步为什么"先写结尾"

结尾那句决定了这一集到底在说什么。**目标定不下来，开头一定散。**
写完结尾句，再回头看开场六句——你会发现很多开场之所以空，是因为根本不知道要走到哪。

### 第 7 步：开场三件套（成本最低的完播率杠杆）

三件事必须在这一步一次做完：

1. **开场钩子**按 R1 §6 六句范式写，前 8 秒零前置知识 → 自查六条硬指标
2. **赌注句**按 R1 §7 写在片头后 3 秒，自带钩子属性 → 对照系列台账的比分
3. **拆字幕**：任何一句 >22 字或预计 >4.5s，**在这一步就拆**成两 cue

→ **QC-27 / QC-28**，**在写 HTML 之前跑**。
此时改字零成本；渲染后发现必然重录重渲。

## 10.1 每集目录的标准文件清单

**先分清两件事**：哪些要你写，哪些由 `engine/` 生成。混在一起会让人以为
「渲染器、混音、字幕全都要自己从头写」，那是 1700 行的工作量。

```
01_<集名>/
├── script_lines.json          ← 你写（每幕句子数组，build_audio.py 的唯一输入）
├── 脚本.md                     ← 你写（幕表 + 逐句台词，给人看）
├── FACTS.md                   ← 你写（事实台账，QC-20）
├── 分镜板.svg                  ← 你写（分镜层，QC-17：必须早于画面代码）
├── standalone.html            ← init_ep.py 生成骨架，你只填三个插槽
│                                  SCENE_CSS / SCENE_HTML / SCENE_JS
│                                （这是整条链里唯一需要创作的文件）
├── timeline.js                ← build_audio.py 生成，不要手写
├── audio/                     ← build_audio.py 生成
│   ├── scene_N.mp3            #   每幕配音
│   ├── final_mix.mp3          #   三层混音（人声 + 音效 + 垫乐）
│   └── subtitles.json         #   句级字幕数据
├── frames_epNN/               ← render.js 生成（frame_%06d.jpg）
├── probe_epNN/                ← render.js probe 生成（抽帧检查）
├── cover_raw.jpg              ← render.js cover 生成（1080×1920，无字幕）
├── 封面候选.jpg                ← mux.py --cover 生成（1200×1600）
├── <系列名>-第NN集-<标题>.mp4    ← mux.py 生成
└── 第NN集-<标题>.srt           ← gen_srt.py 生成
```

**QC-10 每次开新集后必查**：目录里不能有上一集的残留（旧帧、旧脚本、旧集名）。
最常见的事故是「复制了上集目录但忘了改集名」，于是封面和片头都写着上一集的号。

## 10.2 渲染命令

```bash
EP=01_你的主题

# probe：先渲少量关键帧，确认构图与元素位置（不要跳过这步直接全量）
node engine/render.js "$EP" probe 0.8 6 20 40 120 200

# 全量（断点续渲：已存在的帧自动跳过，中断了重跑即可）
node engine/render.js "$EP" full

# 只重渲某一段（改完局部验证用，省时间）
node engine/render.js "$EP" full --from 120 --to 150

# 合片 + 封面
python engine/gen_srt.py "$EP"
node engine/render.js "$EP" cover 7.0
python engine/mux.py "$EP" --cover 7.0
```

`mux.py` 内部的编码参数已经固定，不需要手敲 ffmpeg。三个不能改的值：

| 参数 | 为什么不能改 |
|---|---|
| `-color_range tv` + bt709 三件套 | JPEG 帧是 full-range，不标就会输出 `yuvj420p/pc`，深色渐变底在部分播放器上发灰 |
| `-pix_fmt yuv420p` | 换 444/10bit 在部分安卓机上是黑屏 |
| **不加 `-shortest`** | 音频比画面短（画面多出 `tail_pad` 的定格留白）。加了会按音频截断，把结尾定格整段切掉 —— 实测成片从 19.42s 变成 18.08s，最后一句话刚讲完画面就断 |

编完必查：

```bash
ffprobe -v error -select_streams v:0 \
  -show_entries stream=pix_fmt,color_range,duration -of csv=p=0 成片.mp4
# 期望：1080,1920,yuv420p,tv,<时长>
```

## 10.3 动画引擎接口（已由 `engine/engine.js` 实现）

**这一层不需要你写。** `engine.js` 提供全部驱动能力，你只写"每个元素在 t 时刻长什么样"。

`standalone.html` 里可用的接口：

| 接口 | 作用 |
|---|---|
| `MV.reg(fn)` | 注册一个逐帧回调 `fn(t)` |
| `MV.set(id, opacity, transform?)` | 设置元素不透明度与变换 |
| `MV.vis(t, at, inDur, outAt?, outDur?, hold?)` | 淡入淡出曲线；`hold` 控制交叉溶解的保持时长 |
| `MV.mk(scene, idx)` | 第 scene 幕第 idx 句的起始秒 |
| `MV.P(t, at, dur, ease?)` | 归一化进度 0..1 |
| `MV.out / lin / back / inQ` | 缓动函数 |
| `MV.own(id, tEnd)` | 幕末清场（淡出，不是瞬时归零） |
| `MV.dr(t, t0, t1, dx, dy, s0)` | 相机运镜；**调用前必须能说出分镜哪一句写了推近** |
| `MV.svgEl(tag)` | 创建 SVG 元素 |
| `MV.T` / `MV.SUBS` | 时间轴原始数据 |
| `MV.start()` | 全部注册完后启动（忘了调会在 load 后自动启动） |

> **字幕不归你管，别自己写。** 每句话的字幕是 `engine.js` 自己渲的：
> `build_audio.py` 把每句的 `start/end/text` 写进 `timeline.js` 的 `subtitles`，
> `engine.js` 每帧按当前 `t` 查表、排版（`SUB_MAX=17` 自动折行）、画进 `#sub`。
> **画面代码里不要再画一遍字幕**，否则会出现两层重叠。
> 想某一句不上字幕，在数据里标 `nosub: true`（不是删掉这一句）。
> 幕与幕之间的 `gap`（默认 0.55s）不铺字幕，这是换幕的呼吸，不是丢字。

对外契约（渲染器依赖这三项）：

| 入口 | 契约 |
|---|---|
| `window.videoTimeline.seek(t)` | **纯函数式**：任意 t 都得到相同画面（渲染器逐帧调用，可能乱序、可能跳帧） |
| `window.getDuration()` | 返回 `total + tail_pad`（尾部定格） |
| `window.AUDIO_TIMELINE` | `timeline.js` 提供，engine 读它建索引 |

**三条硬约束**（违反任何一条，渲染结果就会错乱）：

1. `seek(t)` 不能有累积状态。`x += 1`、`el.animate()`、CSS transition 全部禁止 —— 渲染器是跳着 seek 的。
2. 句级节拍来自 `mk()`，不要自己累加固定时长。
3. `nosub` 的 cue 仍在 `SUBS` 里（`mk()` 要用），只是不上屏。

> 字幕排版（17 字上限、逐级降级换行、避头尾）也已在 engine.js 内实现，
> 不需要在场景代码里重写 —— 这是很容易被重复造轮子的一块。

## 10.4 音频构建

```
build_audio.py
  ├── 读 timeline.js（取得每句起止）
  ├── 调 TTS 合成每句 → 按 start 摆放
  ├── 加音效层（whoosh / 落位 / 矛盾音）
  ├── 加垫乐层（分幕性格不同）
  ├── 加片头 BGM（第四层，0–1s 全开，3.5s 淡完）
  └── 母带归一化 -3dBFS → final_mix.mp3
```

**两个常见错误**：

- **先合音频再改脚本**：字数一变，节拍全错。**脚本定稿后才建音频。**
- **人声电平跟着垫乐走**：应该反过来——垫乐给人声让路。

## 11. 交付

**三件套**（命名建议固定，便于归档脚本识别）：

```
<系列名>-第0N集-<集名>.mp4
<系列名>-第0N集-<集名>-封面.jpg
<系列名>-第0N集-<集名>-发布文档.md
```

**归档**：

```bash
MEV_DST=/your/archive python scripts/archive_flat.py      # 全部
python scripts/archive_flat.py ep01                        # 只归档某一集
```

脚本会：平铺复制 → 清理非白名单残留（保留 MANIFEST）→ sha256 回读比对 → 写 `MANIFEST_flat.md`。
**归档后必须回读验证**（列目录、比字节数），不许以"命令没报错"当成功。

### 发布文档必含四节

| 节 | 内容 | 要求 |
|---|---|---|
| 一、标题 | 主标题 + 2 个备选 | ≤20 字；含数字或反常识断言；**不与近 3 集重样** |
| 二、视频描述 | 100–200 字 | 首句 = 钩子；中段 = 本集核心结构一句话；尾句 = 留白问题；**不含"点赞关注"套话** |
| 三、标签 | 8–12 个 | 大类 + 中类 + 具体 + 长尾；**不堆无关热词** |
| 四、封面 | 用哪张 + 裁切说明 | 说明主体位置与平台裁切风险 |

**复盘回写**：更新 `SERIES.md`（交付台账 / 比分 / 钩子台账 / 变体与升维型记录），
并把这一集踩到的坑追加到项目自己的 `LESSONS.md`（下次开新集先读）。

## 12. 常见坑（跨平台通用）

1. **长渲染会崩**：Chrome 连续渲几百帧后随机崩。→ 写 resume 循环：
   `for i in $(seq 1 200); do node render.js; done`，每轮跳过已存帧，
   并在每轮开始前清理 orphan 进程。
2. **端口残留**：每集用完的调试端口不释放。→ 每集递增端口（CDP 9431+2N / HTTP 8891+N），
   或每轮开始前显式 kill。
3. **删文件静默失败**：某些环境的 `rm` / `Remove-Item` 会走回收站垫片，
   失败也不报错。→ 用 Python `shutil.rmtree` 并**回读验证目录确实不存在**。
4. **TTS 不给句级时间戳**：多数服务只返回整段音频。
   → 用 `silencedetect` 反推句级节拍，或用固定速率 + 人工校准。
5. **大段中文写进 .py 会炸**：全角引号被编辑器规范化成 ASCII 引号 → SyntaxError。
   → 文案抽到独立 `.md` / `.json` / `.txt`，代码只读文件。
6. **程序生成的图片必须逐张打开看**再报完成。生成"成功"不等于"正确"。
7. **图生图 API 的参数名各家不同**（`ratio` / `size` / `aspect_ratio`），
   传错会**静默忽略**而不是报错。→ 第一次调用就验证输出尺寸。
8. **判断某个模型/端点是否存在，唯一判据是实机调用**，不许凭检索下结论。
9. **批量删帧会被安全垫片拦截**（触发确认）。→ 删整堆帧前先 `os.rename` 改名留作备份，
   渲染器会自动建新目录。
10. **调试脚本 spawn 浏览器可能 ENOENT**（沙箱只放行已知脚本路径）。
    → 不要写独立的 spawn 脚本，在现有 `render.js` 里加一个 mode。
11. **旧帧备份目录会累积**（每版可能几百 MB 到 1GB）。
    → 定稿交付后清理，只留最终版。
12. **编码色域**：见 §10.2 的 `-color_range tv`。这是跨项目最常复发的一个坑。
