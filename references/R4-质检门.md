### 21-D 运动依据门（2026-10-16 改写，取代旧的"每句必须动"）

**旧口径（作废）**：每句配音期间必须有相邻帧像素变化，否则判"冻结句"FAIL。
**作废原因**：这个口径逼着给静止的东西加无理由运动（ep01 因此加了全局镜头呼吸），
与 4.2b 直接冲突。**静止可以是正确答案。**

**新口径（两条，都判 FAIL）**：

| 方向 | 判据 | 抓什么 |
|---|---|---|
| **A 该动的必须动** | 元素带 `data-motive` 标注 → 其所属拍内相邻帧差 **必须 > 0.02** | 分镜写了"球落下"但代码没实现 |

**像素口径降级为诊断**：仍然逐句输出 `maxAdj`（全句最大相邻帧差），但**不再因"整句静止"判 FAIL**。

**脚本**：`verify/qc21d_motion2.py`（DOM 口径，按 `data-motive` 校验）＋
`verify/qc21d_motion.py`（像素口径，仅诊断输出）。

**三方对账仍保留**：DOM 报"15 句无新元素入场"这类结论，必须与像素证据交叉核对后才能采信——
幕4 的按印驱动 `transform` 而非 `opacity`，DOM 会漏报。**判停以像素为准，DOM 仅作辅助诊断。**

### QC-12 封面门 · 四项验收 + 设计纪律（2026-10-16 加强）

**四项验收**：① 取自成片真实帧或程序化渲染（**禁 AI 生成占位图**）② 字号手机可读 ③ 主体不被平台 UI 裁切（核心内容在 `y 220–1300`）④ 与 v5 视觉系统一致（**孔雀青底 + 琥珀 accent**，见 §4.6）。

**设计纪律（用户 2026-10-16 要求"更吸引人、有创新性、要有数的元素调调"，仍然有效）**：

1. **必须有"数"的视觉元素**，且要与本集主题同构，不是贴个数字上去。
   可用母题：刻痕列 / 数列条纹 / 分数分割 / 对称轴 / 数列瀑布 / 网格点阵 / 圆周率螺旋。

2. **封面主视觉 = 本集的"视觉签名"**：每集必须有一个只属于它的图形母题（ep01 刻痕列 / ep02 60 表盘 / ep03 点阵 / ep04 空圆 / ep05 红黑算筹 / ep06 正方形对角线），放在封面底部中央。**这个签名必须与片头 0.3s 出现的图形同一个**——观众刷到封面时看到的，就是点开后第一眼看到的。
3. **创新性自查**：把封面缩到 1/4 大小（模拟 feed 缩略图），问"这一格凭什么让人停下来"。

### QC-23 空画面门 · 判据与阈值（ep01 实测标定）

- **像素判据**：主画面区（y < 1330，字幕带以上）**最大亮度**。
  交付档阈值 **60**（严格档 100 一并输出，便于复核不掩盖问题）。
  理由：背景 `#07080C` 亮度 ≈ 7，峰值亮度 60 时对比度约 8×，手机屏稳定可辨；
  而峰值 79 / 89 那种"细线图形以 0.4 不透明度交叉溶解"的帧，逐帧目视确认人物与器物
  轮廓清清楚楚，判成空画面与目视不符。**不许**用"亮像素计数"做判据 —— 细线图形
  （时间轴 / 链条 / 刻痕）全不透明时计数也很低（实测 a5-chain 在 o=1 时超阈值仅 2967 px），
  与真空画面的数量级相同，会大量误判。
- **结构判据（advisory，不单独判 FAIL）**：同帧内排除底噪层（`stage`/`vig`/`stars`/`sub`/`subT`）
  后，元素**有效**不透明度（自身 × 全部祖先）的最大值。它抓"元素根本不在"，
  与像素判据抓的"元素在、但读不出来"互补。落在 0.55–0.62 的帧一律伴随峰值亮度 ≥ 110
  （交叉溶解中点），不算问题。
- **开场 t < 0.5s 允许留黑**（片头淡入）。
- 脚本：`verify/qc23_density.py`（像素）、`verify/qc23b_structural.js`（结构）。

### 拍级交接契约（QC-23 的根因纪律）

**进场拍的第一个内容元素必须在下车拍开始变暗之前达到 o = 1。**
`vis()` 的出场在 `outAt + OUT_HOLD` 之后才开始降，所以入场点必须 ≤ `outAt + OUT_HOLD − inDur`。
违反这一条，交接处两块同时落到 0.3–0.5，细线图形直接读成黑。ep01 实测：原版 14 段 / 约 12s
"只有字幕、主画面全黑"，全部由这一条被违反造成。
**例外**：设计上本就**同框嵌合**的复合图（两块内容互相落在对方空隙里）应当**同框共存再抽走**，
而不是交叉溶解 —— 给 `vis()` 传第 6 个参数 `hold=0`，等入场块 o=1 后再快速抽走出场块。

### 9.1 QC-26 FAIL 的三时刻像素分流（ep05 定稿，2026-10-19）

**DOM 报出的 bbox 相交有一半是假的**（父子同卡、行高虚高、字形相隔 1px）。直接按 bbox 修 = 白改一轮。判据：

对每个 FAIL 对，取 bbox 交集区，测**三个时刻**的墨迹像素数：`A 单独` / `B 单独` / `重叠`。

```
base = max(A单独, B单独)
增量 = 重叠 / base - 1
```

| 增量 | 判定 | 动作 |
|---|---|---|
| **≤15%** | **假告警**（bbox 虚高 / 同卡父子相邻 / 不增量） | 不动代码，把该对写进 GHOST 白名单 |
| **15%–35%** | 灰区 | 目视关键帧确认再定 |
| **≥35%** | **真压字** | 修（优先位移，其次时序，最后才动版面） |

**阈值必须双档**：`62`（捕 0.4 opacity 的半透明文字，亮度≈98）与 `110`（实墨迹）。只用 110 会漏掉半透明层，A/B 全区统计为 0 → 误判成"不增量"。
脚本模式：`_audit/_ep05_pixelprobe.py`（CASES 表逐条列 `label / t_ab / A_box / B_box / t_a_only / t_b_only`）。

### 9.2 换页位移模式（QC-26 的正解，ep05 七处验证）

**症状**：相邻两张卡在**同一区域前后交替**（旧卡退场与新卡入场时间重叠），bbox 必然相交，QC-26 FAIL，同时常伴 QC-24。

**错误解法**：缩短新卡入场窗口。→ 会让中间出现一段"两块都没到"的真空，QC-23b 空屏门直接挂。

**正确解法：反向位移（空间错开，时间照旧交叠）**

```
旧卡退场：translateY 下沉 40–70px（退场区间内线性）
新卡入场：从上方 -120 ~ -130px 滑回 0（1.0–1.2s 缓出）
```

两者时间依然重叠（QC-23b 保持 0 段），但在重叠时刻它们**已经不在同一水平带**，bbox 不再相交。
ep05 用此法 7 处 → QC-26 四轮收敛 `FAIL=0`，QC-24 顺带从 5 对降到 0。

**参数经验**：下沉 40px 配 1.0s 入场够用；若入场元素较大（>400px 高）或重叠窗口长（>1s），用 130px + 1.2s。
**注意**：位移量不够时在"重叠时刻"只剩几十像素，等于没躲开——要按**重叠时刻的实际剩余位移**验算，不是按起始值。

### 9.3 拍表必须实测，不能推算（ep05 血泪，运动审计根因）

**现象**：按 `mk(scene, idx)` 推算某动画的 onset 是 161.84s，取 `t=162.2` 采样 → 帧差 **0.000%** → 判"该动的没动" FAIL。
实际该元素在 **158.33–159.10s** 就完成了变化（比推算早 3.6s）→ 采样窗口落在静止段，是**假 FAIL**。

**为什么不一致**：`mk()` 给的是**句起点**，但元素动画可能由句内某个子事件（逐节点点亮、逐格填色、flash 步进）驱动，其真实 onset 由代码内的时间常数决定，不是句起点。

**正确流程（三步，不可跳）**：

1. **先逐帧扫真 onset**：点状/步进元素用「**区域亮像素数 > N**」逐帧扫描，找到数值跳变的那一帧；线状元素扫「区域内墨迹带宽度变化」。
2. **再定采样窗口**：窗口必须**跨在 onset 上**（onset ±0.25s 内），不能落在段内。
3. **最后才写进审计表**，并在脚本 docstring 里记下实测值，注明"推算值 X，实测 Y，差 Z 秒"。

**另一个坑：细线要用窄带分母**。数轴线身只占 y767–786 共 20px，若用整屏 region（y440–1000）做分母，帧差被稀释到 0.291% 判 FAIL；收窄到 y760–795 后实测 **1.229%** PASS。**小元素必须用 localized 区域**（M-16/M-70 同一根因）。

### 9.4 体检门 QC-29 · `epcheck.py`（v6 新增）

**CK-14 必须人工，原因**：程序判不了"画面对不对题"。ep01 曾出现台词在讲"羊与石子一一配对"、画面在放无关图表，所有机器门全过。做法：`epcheck.py` 会列出 6 张待查帧的**绝对路径**，逐张打开对着台词看，答不出就回分镜层。

**为什么这些必须单独成门**：QC-21A 查安全区、QC-23 查空画面、QC-26 查压字——它们都假设"素材是对的、编码是对的"。而 CK 系列查的恰恰是**上游假设本身**：帧有没有缺、字有没有超出音频、片头到底有没有 BGM、颜色范围对不对。**上游错了，下游全白查。**
