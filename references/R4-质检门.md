# R4 · 质检门（QC-0 ~ QC-29）

> 这份文档解决一个问题：**怎么证明"做完了"不是自我感觉。**
> 读它的时机：交付前必读；出问题时按症状来查。

---

## 8. 逐帧验收（QC-21）

一集 3 分钟 ≈ 4300–5000 帧。**不要说"我用眼睛看完了每一帧"**（假话，也不可能）。
做三层，每层拿得出证据：

| 层 | 内容 | 覆盖 |
|---|---|---|
| **21-A** | 全帧机器判定：死画面/黑帧/闪帧/安全区越界/文字溢出/元素重叠/音画同步 → 异常清单**修到为空** | 100% 帧 |
| **21-B** | 关键帧目视（每镜首中末帧 + 动画节点 + 每 2s 抽样 + 文字卡首末帧），**逐张打开看** | 120–160 张 |
| **21-C** | 高难段全程 4fps 抽帧目视（复杂图形、形变、粒子、多元素同框） | 全段 |
| **21-D** | 文本-画面-声音三方对账 **＋ 运动依据门** | 双向可查 |

**判停：有异常帧未修 → 不交付。**
（机器查结构性错误，查不出"难看"和"看不懂"——所以 21-B 必须真的看图。）

### 21-D 运动依据门

**旧口径（作废）**：每句配音期间必须有相邻帧像素变化，否则判"冻结句"FAIL。
**作废原因**：这个口径逼着给静止的东西加无理由运动，与 R2 §4.2b 直接冲突。
**静止可以是正确答案。**

**新口径（两条，都判 FAIL）**：

| 方向 | 判据 | 抓什么 |
|---|---|---|
| **A 该动的必须动** | 元素带 `data-motive` → 其所属拍内相邻帧差 **必须 > 0.02** | 分镜写了"球落下"但代码没实现 |
| **B 不该动的不许动** | 元素无 `data-motive` → 其所属拍内相邻帧差 **必须 = 0** | 无理由漂移 / 全局呼吸残留 |

**像素口径降级为诊断**：仍逐句输出 `maxAdj`（全句最大相邻帧差），
但**不再因"整句静止"判 FAIL**。它的用途是提示"这句完全没动"——
如果分镜上这句就该是静止特写，那就是对的。

**三方对账保留**：DOM 报"15 句无新元素入场"这类结论，必须与像素证据交叉核对后才能采信。
幕末的 `transform` 驱动（而非 `opacity`）会让 DOM 漏报。**判停以像素为准，DOM 仅作辅助诊断。**

### QC-12 封面门 · 四项验收

1. **取自成片真实帧或程序化渲染**（**禁 AI 生成占位图**）
2. **字号手机可读**（缩到 feed 缩略图大小仍能读出主标题）
3. **主体不被平台 UI 裁切**（核心内容在 y 220–1300）
4. **与全系列视觉系统一致**（同一底色、同一 accent，见 R2 §4.5–4.6）

**设计纪律**：

1. **封面主视觉 = 本集的"视觉签名"**：每集必须有一个只属于它的图形母题，
   放在封面底部中央。**这个签名必须与片头里出现的图形是同一个**——
   观众刷到封面时看到的，就是点开后第一眼看到的。
2. **创新性自查**：把封面缩到 1/4 大小（模拟 feed 缩略图），问"这一格凭什么让人停下来"。
   答不出来就重做。**不许用"深色底 + 居中大字"这种零信息版式交差。**
3. **数字必须是真数字**（来自 `FACTS.md` 验算过的断言），封面上的数与口播必须一致。
   历史上出现过台账写 29、实际 168 的不一致——这类错误观众一定会发现。

### QC-23 空画面门 · 判据与阈值

- **像素判据**：主画面区（y < 1330，字幕带以上）**最大亮度**。
  交付档阈值 **60**（严格档 100 一并输出，便于复核不掩盖问题）。

  理由：深色背景亮度 ≈ 7，峰值 60 时对比度约 8×，手机屏稳定可辨；
  而峰值 79 / 89 那种"细线图形以 0.4 不透明度交叉溶解"的帧，
  逐帧目视确认轮廓清清楚楚，判成空画面与目视不符。

  **不许**用"亮像素计数"做判据——细线图形（时间轴 / 链条 / 刻痕）
  全不透明时计数也很低，与真空画面的数量级相同，会大量误判。

- **结构判据（advisory，不单独判 FAIL）**：同帧内排除底噪层
  （`stage`/`vig`/`stars`/`sub`/`subT`）后，元素**有效**不透明度
  （自身 × 全部祖先）的最大值。它抓"元素根本不在"，
  与像素判据抓的"元素在、但读不出来"互补。

- **开场 t < 0.5s 允许留黑**（片头淡入）。

### 拍级交接契约（QC-23 的根因纪律）

**进场拍的第一个内容元素必须在下车拍开始变暗之前达到 o = 1。**

`vis()` 的出场在 `outAt + OUT_HOLD` 之后才开始降，所以入场点必须
≤ `outAt + OUT_HOLD − inDur`。违反这一条，交接处两块同时落到 0.3–0.5，
细线图形直接读成黑。（历史上曾出现约 12 秒"只有字幕、主画面全黑"，全部由这一条被违反造成。）

**例外**：设计上本就**同框嵌合**的复合图（两块内容互相落在对方空隙里）应当
**同框共存再抽走**，而不是交叉溶解——给 `vis()` 传 `hold=0`，
等入场块 o=1 后再快速抽走出场块。

### 9.1 QC-26 FAIL 的三时刻像素分流

**DOM 报出的 bbox 相交有一半是假的**（父子同卡、行高虚高、字形相隔 1px）。
直接按 bbox 修 = 白改一轮。

**做法**：对每个 FAIL 对，取 bbox 交集区，测**三个时刻**的墨迹像素数：
`A 单独` / `B 单独` / `重叠`。

```
base = max(A单独, B单独)
增量 = 重叠 / base - 1
```

| 增量 | 判定 | 动作 |
|---|---|---|
| **≤15%** | **假告警**（bbox 虚高 / 同卡父子相邻 / 不增量） | 不动代码，把该对写进 GHOST 白名单 |
| **15%–35%** | 灰区 | 目视关键帧确认再定 |
| **≥35%** | **真压字** | 修（优先位移，其次时序，最后才动版面） |

**阈值必须双档**：`62`（捕 0.4 opacity 的半透明文字）与 `110`（实墨迹）。
只用 110 会漏掉半透明层，A/B 全区统计为 0 → 误判成"不增量"。

### 9.2 换页位移模式（QC-26 的正解）

**症状**：相邻两张卡在**同一区域前后交替**（旧卡退场与新卡入场时间重叠），
bbox 必然相交，QC-26 FAIL，同时常伴 QC-24。

**错误解法**：缩短新卡入场窗口。→ 中间会出现一段"两块都没到"的真空，QC-23 空屏门直接挂。

**正确解法：反向位移（空间错开，时间照旧交叠）**

```
旧卡退场：translateY 下沉 40–70px（退场区间内线性）
新卡入场：从上方 -120 ~ -130px 滑回 0（1.0–1.2s 缓出）
```

两者时间依然重叠（QC-23 保持 0 段），但在重叠时刻它们**已经不在同一水平带**，bbox 不再相交。

**参数经验**：下沉 40px 配 1.0s 入场够用；若入场元素较大（>400px 高）
或重叠窗口长（>1s），用 130px + 1.2s。

**注意**：位移量不够时在"重叠时刻"只剩几十像素，等于没躲开——
要按**重叠时刻的实际剩余位移**验算，不是按起始值。

### 9.3 拍表必须实测，不能推算

**现象**：按 `mk(scene, idx)` 推算某动画的 onset 是 161.84s，取 `t=162.2` 采样
→ 帧差 **0.000%** → 判"该动的没动" FAIL。
实际该元素在 **158.33–159.10s** 就完成了变化（比推算早 3.6s）→ 采样窗口落在静止段，是**假 FAIL**。

**为什么不一致**：`mk()` 给的是**句起点**，但元素动画可能由句内某个子事件
（逐节点点亮、逐格填色、flash 步进）驱动，其真实 onset 由代码内的时间常数决定。

**正确流程（三步，不可跳）**：

1. **先逐帧扫真 onset**：点状/步进元素用「区域亮像素数 > N」逐帧扫描，
   找到数值跳变的那一帧；线状元素扫「区域内墨迹带宽度变化」。
2. **再定采样窗口**：窗口必须**跨在 onset 上**（onset ±0.25s 内），不能落在段内。
3. **最后才写进审计表**，并在脚本 docstring 里记下实测值，
   注明"推算值 X，实测 Y，差 Z 秒"。

**另一个坑：细线要用窄带分母**。数轴线身只占 20px 高，
若用整屏 region 做分母，帧差被稀释到 0.291% 判 FAIL；收窄到线身 ±15px 后实测 1.229% PASS。
**小元素必须用 localized 区域。**

### 9.4 体检门 QC-29 · `epcheck.py`

> **和 QC 门的分工**：QC 门（0–28）判"这一集做得好不好"，需要逐帧/逐元素深查，慢；
> 体检门（29）判"这一集有没有低级错误"，30 秒出结果，**可以在渲染完、合片后、
> 归档前、改完任何一处随时跑**。
> 两者不替代：体检过 ≠ 能交付，但**体检 FAIL 一定不能归档**。

```bash
python scripts/epcheck.py <集目录>              # 默认抽 9 帧
python scripts/epcheck.py <集目录> --frames=15
python scripts/epcheck.py <集目录> --strict      # WARN 也算失败
```

自动发现集目录内的成片 / srt / final_mix / frames / 封面，缺项记 SKIP 不中断。

| 编号 | 检查项 | 判据 | 级别 | 抓什么真实故障 |
|---|---|---|---|---|
| CK-01 | 音画时长 | 视频 − 音频 ∈ [−0.5, +5.0]s | FAIL | 视频比音频短=结尾被截；超 5s=帧数多了 |
| CK-02 | 字幕末条越界 | 最后一条 cue.end ≤ 音频时长 + 0.3s | FAIL | 最后一句字幕被切掉 |
| CK-03 | 字幕条重叠 | 相邻 cue 不得 start < 前一条 end | FAIL | 两条字幕同屏打架 |
| CK-04 | **片头 BGM** | 0–1s RMS 比 2–3s 高 ≥ 6dB | FAIL | 片头 BGM 有没有真做上 |
| CK-05 | 字幕空洞 | 相邻 gap ≤ 1.5s | WARN | 某段画面没台词（观众以为卡了） |
| CK-06 | 纯色 / 黑帧 | 抽样帧灰度 std < 3.0 | FAIL | 渲染中断留下的黑帧 |
| CK-07 | 画面模糊 | 抽样帧拉普拉斯方差 < 80 | WARN | 图片被上采样 / 截图拉伸 |
| CK-08 | 纯文字帧 | 主画面区（y300–1330）墨迹占比 < 0.05% | WARN | 只有字幕没有图形（讲空话） |
| CK-09 | 帧序完整 | `frame_%06d.jpg` 从 0 到 N 连续无缺无重 | FAIL | 渲染断点没补上，成片会跳 |
| CK-10 | 编码合规 | 1080×1920 / 24fps / h264 / **yuv420p + tv** / AAC | FAIL | 含 `yuvj420p` full-range 陷阱 |
| CK-11 | 封面尺寸 | 1200×1600（3:4） | FAIL | 封面被裁 / 比例错 |
| CK-12 | 结尾卡停留 | 视频时长 − 音频时长 ≥ 1.3s | FAIL | 结尾卡一闪而过读不完 |
| CK-13 | 文件体积 | 8–60 MB | WARN | 过小=渲错，过大=混进照片 |
| CK-14 | **图形语义匹配** | 抽 6 拍拍，逐拍问"这图画的是这句话吗" | **人工** | 画不对题 |

**CK-14 必须人工，原因**：程序判不了"画面对不对题"。
曾出现台词在讲"A 与 B 一一配对"、画面在放无关图表，所有机器门全过。
做法：`epcheck.py` 会列出 6 张待查帧的**绝对路径**，逐张打开对着台词看，
答不出就回分镜层。

**为什么这些必须单独成门**：QC-21A 查安全区、QC-23 查空画面、QC-26 查压字——
它们都假设"素材是对的、编码是对的"。而 CK 系列查的恰恰是**上游假设本身**：
帧有没有缺、字有没有超出音频、片头到底有没有 BGM、颜色范围对不对。
**上游错了，下游全白查。**
